EverRoom 指南

开始使用 EverRoom

用一个 Room 集中管理项目资料、文档和 Agent 会话。

第一次使用

  1. 安装并完成引导

    配置模型，填写工作背景，并创建第一个 Room。

  2. 连接一份资料

    在“数据源”中添加项目文件夹，等待同步完成。

  3. 打开 Room

    确认目标、关联资料和概览是否正确。

  4. 完成一个小任务

    例如：“根据当前 Room 的资料列出本周待办，并标注来源。”

支持平台

macOS（Apple Silicon）为主要版本；移动端提供 iOS TestFlight 和 Android 测试版。

开始使用

下载并安装 macOS 版

桌面端支持 Apple Silicon（M 系列芯片），前往 GitHub Releases 下载。

安装步骤

  1. 下载安装包

    在 Releases 选择最新的 Pre-release，下载文件名包含 arm64.dmg 的文件。

  2. 安装应用

    打开 DMG，将 EverRoom 拖入“应用程序”。

  3. 打开应用

    从“应用程序”启动 EverRoom，按需授予文件、麦克风或系统音频权限。

移动端测试版

通过 TestFlight 测试 iOS 版，或下载 Android 测试版。

开始使用

首次启动

完成一次设置后，就可以连接资料并开始工作。

1. 配置模型

登录 EverRoom 账号使用托管配置，或填写兼容模型的 Base URL、模型名和密钥。通过连接测试后继续。

2. 完成引导

  1. 填写工作背景

    说明你的角色、近期目标和希望 Agent 采用的协作方式。稍后可在“设置 → 记忆引导”中修改。

  2. 创建第一个 Room

    选择“项目”或“主题”，填写清楚的名称和目标，例如“官网改版 — 完成上线前验收”。

  3. 选择识别范围

    只授权当前项目目录，不要直接选择整个主目录。

3. 确认已就绪

进入首页后，Gateway 不再显示启动或连接异常，且侧栏可以打开“数据源”和“Context Room”，即可继续。

切换语言

打开“设置”，将界面语言切换为简体中文或 English。

使用指南

连接第一份资料

先添加一个小型项目文件夹，确认同步结果正确。

添加本地文件夹

  1. 打开入口

    在侧栏打开“数据源”，点击“连接数据源”。

  2. 选择类型

    选择“文件识别文件夹”，再选择项目目录并允许访问。

  3. 等待同步

    目录出现在数据源列表后，等待扫描完成。点击目录可查看已识别文件。

连接其他来源

GitHub填写仓库地址和分支；私有仓库还需 Token。
Obsidian选择 Vault，可作为项目 Room 持续挂载。
在线服务选择连接器，在浏览器完成授权后返回 EverRoom。

确认连接成功

  • 数据源列表中没有失败提示。
  • 展开来源可以看到预期文件。
  • 打开文件可查看正文、来源和版本。
原文件不会被修改断开来源只会删除 EverRoom 保存的副本和索引，不会删除本地或云端原文件。

使用指南

建立 Context Room

一个 Room 对应一个明确的项目、主题、人物或长期目标。

创建 Room

  1. 打开“Context Room”，在“我的 Room”右侧点击“+”。
  2. 选择类型，填写名称、目标和必要背景。
  3. 点击“创建 Room”；如出现相似 Room，先检查已有内容，避免重复。

加入工作资料

打开 Room 后，在资源区域添加相关来源或导入 Markdown。只放与当前目标有关的资料。

检查 Room

  • “概览”中的目标与当前工作一致。
  • 资料可以打开，并能回到原始来源。
  • 人物、项目和时间线没有明显误关联；有误时取消关联。

开始第一个任务

在当前 Room 打开 Agent，输入具体任务和输出格式。例如：

阅读当前 Room 的资料，整理已确认的决定、未解决的问题和下一步行动。每项附上来源。

使用指南

创建文档并使用 Agent

文档保存在 Room 中；“文档”页用于集中查找和打开。

新建文档

  1. 打开目标 Room，在资源区域点击“新建文档”。
  2. 使用能说明用途的标题，例如“8 月 28 日产品评审结论”。
  3. 写下目标、已知信息或希望 Agent 继续处理的提纲。

编辑与历史

直接编辑正文。需要核对改动时，打开文档操作菜单查看历史版本。

让 Agent 修改文档

在右侧 Agent 面板说明目标、范围和输出要求。涉及资料时要求引用来源；涉及改写时先检查变更，再接受结果。

把当前文档改成简短的会议纪要。保留决定、负责人和截止日期，不补充资料中没有的信息。

导出

在文档操作中选择 Markdown、PDF 或 DOCX。导出后打开文件检查标题、表格和图片。

使用指南

检查和管理记忆

记忆用于跨会话保留背景，不应代替原始资料。

查找一条记忆

  1. 打开“记忆”，在顶部搜索人物、项目或决定。
  2. 在“原子记忆”“对话”“文档”或“场景”中打开结果。
  3. 通过来源信息回看原文，再用于重要任务。

保持内容准确

在“画像”检查长期背景，在“过滤规则”说明哪些资料应保留或忽略。发现过期或错误内容时及时修正或删除。

资料没有进入记忆

打开“导入记录”，查看过滤判定和处理状态。被误过滤的条目可选择“恢复”。

服务未就绪

记忆服务不可用时可以先跳过；本地文档和基础工作区仍可使用。

使用指南

录音与转写

录制麦克风或 Mac 系统音频，再检查转写和总结。

首次授权

录制麦克风时允许“麦克风”权限；录制电脑音频时，在 macOS“隐私与安全性”中允许“屏幕与系统音频录制”，然后完全退出并重启 EverRoom。

完成一次录音

  1. 打开录音入口，选择“麦克风”或“电脑音频”。
  2. 选择语言并开始录制；录音需超过 10 秒。
  3. 停止录音，等待状态从“处理中”变为“已完成”。

检查结果

在“现实感知”打开该事件，播放录音并校正姓名、数字和专有名词，点击“保存逐字稿”。总结会根据修改后的内容更新。

使用指南

查看任务与日记

跟踪 Agent 运行，处理重复任务，并回看每日活动。

查看 Agent 任务

打开“办公室”查看运行中、已完成或失败的任务。打开任务可查看过程和结果；失败时先读错误信息，再决定重试。

创建计划任务

  1. 打开“计划任务”，新建任务并写清执行内容。
  2. 选择运行时间和重复周期。
  3. 先手动运行一次，确认使用的 Room、资料和输出正确，再启用计划。

回看一天

打开“日记”并选择日期。没有内容时点击“生成日记”；生成后通过“查看来源”核对对应文档、录音或活动记录。

开发

从源码运行

需要 Node.js 22+ 和 pnpm 11。

启动项目

git clone https://github.com/NxcoreAI/EverRoom.git
cd EverRoom
corepack enable
pnpm install
pnpm dev

配置 Agent Runtime

复制 .env.example 为 .env。默认 fake Runtime 不请求模型；使用真实 Agent 时填写 NXCORE_AI_* 配置。

常用命令

pnpm dev启动桌面端
pnpm typecheck类型检查
pnpm test运行测试
pnpm build构建项目

管理

设置与数据

管理账号、模型、语言、权限和本地数据。

账号与模型

登录可使用托管配置；也可以手动配置兼容模型端点。

本地数据

macOS 默认数据目录：~/Library/Application Support/NxCore/。

清除数据

“清除全部用户数据”会删除 EverRoom 的本地数据库、记忆、录音和设置，但不会删除原始文件夹或云端数据。

管理

故障排查

先检查版本、权限和网络。

应用无法打开

确认安装包来自官方 Releases，且文件名包含 arm64.dmg。在 macOS“隐私与安全性”中查看拦截原因。

Gateway 未就绪

完全退出并重启 EverRoom。开发模式可查看终端和 ~/Library/Application Support/NxCore/logs/。

模型连接失败

检查 Base URL、模型名、API 类型和密钥。

文件未出现

检查文件夹权限、文件格式和数据源状态。

没有录到声音

检查麦克风或系统音频权限，修改后重启应用。

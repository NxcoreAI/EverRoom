EVERROOM 行业版 · FA 效果总览

从原始材料到最终成果

三类 Room 承载项目、人物与投资机构，每一步的产出都带着来源与确认，成为下一步的依据——从资料进入，到材料、名单、简报，最后回流为下一轮的知识与任务。

资料进入 Room→ 核实事实→ 机构档案→ 制作材料→ 投资人匹配→ 会前准备→ 会后反馈→ 知识回流 ↺

以下效果均为示意数据；右侧标注的接口、数据表与算法为 FA 分支已落地的真实实现。

01

资料进入 Room

产品文档 · 环节 1 项目获取与登记 / 环节 5 材料收集与核验

项目适合谁？应该找谁？机构投了谁？——三类 Room 分别回答。

输入
BP、会议记录、推荐信息、机构官网与投资组合页
处理
按长期对象分房：项目、人物、投资机构；同一场会议可关联多个 Room，原始来源保持一致
产出
带关系的 Room 网络——任职、投资、创始、介绍四类语义关系

关联不意味着开放权限：竞争项目和敏感关系备注仍按授权隔离。

实现ContextRoomKind 新增「机构」一等实体 · RoomRelationManualType：founder_of / employed_by / invested_in / introduced_by（REST 校验同步）

02

核实事实

产品文档 · 环节 5 材料收集与核验

关键数字和观点区分事实、分析、预测、意见与未知，并回链来源。

输入
Room 内材料与访谈记录
处理
实体抽取时逐条标注五档之一；公司预测不得标 fact，行业平均标 analysis，拿不准宁可标低；数字带口径元数据
产出
带分级的事实库——下游 BP 取数、简报聚合只取 grade = fact

未标注的事实不冒充事实：解析到非法分级时回落为 opinion，旧格式自动兼容。

实现room_entity_facts 增 grade 五档 + numeric 元数据（value/unit/period/currency/audited/verifiedBy）· entity-extraction Skill 教五档标注 · parseExtractionResponse 严格解析

03

机构档案

产品文档 · 环节 8 前置 · 机构情报与私有关系知识

机构既要能回答「投了谁」，也要帮助理解「为什么可能适合这个项目」。

输入
公开投资记录 + 团队私有交流（会议、电话、邮件）
处理
结构化直读不经模型；来源与确认走确认制；投资事件不可变，修正走删除重录；明确表达与行为归纳分开标记
产出
基金 / 投资案例 / 任职三张表 + 带来源时间确认人的私有信号

历史投资方向与本期基金策略分别保留——「投过消费硬件」与「本期优先企业服务」同时成立，差异交给人判断。

实现迁移 0086_fa_institution_archives（88 行 DDL）· /v1/fa/institutions/:roomId/{funds,investments,positions}（CRUD + confirm + 软删 + 幂等去重）

04

制作材料

产品文档 · 环节 7 BP 与融资材料制作

在项目 Room 中调用已核事实起草 PPT、Word、One-pager 和 FAQ。

输入
项目事实库（只取 fact 档）+ 赛道选型结论
处理
主 Agent 写脚本前按赛道取模块骨架，逐模块成页：赛道决定模块顺序，模块决定内容要求；数字与引用可回链来源
产出
可编辑材料与对外候选版本，保留版本与修改依据

选型是决策树不是生成任务：卖什么 → 怎么赚钱 → 已验证什么 → 本轮要证明什么，六问定模板。

实现T01–T18 × M01–M13 配置库 + 四种讲述顺序 + 三档发展阶段 · bp_template_get 工具 · slides 脚本直生（pptxgenjs）

05

投资人匹配

产品文档 · 环节 8 投资人筛选与匹配

先核对阶段、币种、票面及冲突，再解释匹配理由和未知条件。

输入
项目条件（轮次 / 金额 / 赛道 / 可比公司）+ 全部机构档案
处理
两阶段：硬筛不合格必须带理由出局；数据缺失标 unknown 不判死。再按赛道认知、阶段匹配、决策可达、当前姿态、数据完整度加权评分
产出
带得分依据的候选名单——最终名单与时机由合伙人确定

投过类似公司既可能是行业认知，也可能是组合矛盾——每条可比公司给「认知 / 冲突」双解释。

实现screenInstitutions 两阶段算法（fa-archive/matching.ts）· 每项得分带 basis · 可比公司 synergy / conflict 双解释

06

会前准备

产品文档 · 环节 10 路演与会前准备

汇总机构近期投资、参会人关注点、历史互动和未完成承诺。

输入
项目 Room + 机构 Room + 参会人物 Room
处理
纯读聚合：基金投资期、投委会与可领投联系人、投资案例与组合冲突、历史反馈（含未确认草稿）、未兑现重启条件、项目已核事实
产出
会前 Brief + 披露边界 + 会议目标，沟通策略由负责人确认

重启条件未满足的机构出现在「不该打扰」清单里——会前先看到，避免踩线。

实现buildMeetingBrief 聚合（fa-archive/brief.ts）· 机构/人物信号事实 + 未确认 draft 一并供会前知悉

07

会后反馈

产品文档 · 环节 11 会后反馈与跟进

提取问题、关注点、反馈、承诺和任务，分别提出待确认变更。

输入
会议记录（获授权部分）
处理
AI 整理为草稿：四分类记录态度，暂缓 / 观察必须带标准原因码；重启条件决定何时可再次接触——AI 只产建议，人确认才回写
产出
负责人确认后的反馈记录 + 按分类生成的跟进任务

不会因一句「先不聊」就把人物或机构永久标记为「不投这个赛道」——拒绝原因标准化，重启条件可复核。

实现FaFeedbackService：createDraft（pass/watch 必须带原因）· confirm（三路回写 + 任务定时限）· dismiss · 幂等

08

知识回流

产品文档 · 环节 11 / 15 复盘与持续积累

每次更新可确认：确认后的信号各回各的 Room，成为下一轮依据。

输入
已确认的反馈与跟进安排
处理
三路回写：项目侧进事实库 grade=fact；人物与机构侧信号挂对应 Room——个人观点不上升为机构策略；任务按分类定时限与优先级
产出
更新后的事实库、画像信号与跟进任务，下次会前简报自动带上

团队积累的经验持续参与下一笔交易：接续他人工作只需进入 Room。

实现三路信号各挂各的 Room（个人观点挂人物房，不上升机构策略）· 跟进任务：strong_interest 24h / interest 48h · roomLocalActions

↺

最后一格回到第一格

从项目进入到交易复盘，资料、判断依据、交付物和下一动作始终在同一条工作线上——这一次会议的产出，是下一次工作的依据。

## 二、Bug 修复（按用户能感知的现象）

### 1. 满屏无意义小字、很「AI 味」【已提交】

- **原来**：字号由引擎按绘图区自动推；页脚、图注、图表轴/图例/数据标签写死 9~11pt（代码里三处 `Math.max(9, caption)`、瀑布图 `Math.min(caption, 11)`）。
- **现在**：最小字号由场景表给定；页脚/图注/图表小字统一取场景 caption 档（投影 13pt / 研读 11pt）；低于硬下限（投影 caption 12pt / 研读 10pt）不再出现。
- **验收**：一页上不应再出现 9pt / 10pt 的字（研读档下限 10pt 除外）。

### 2. 两根柱子配十条 Y 轴刻度【已提交，需重建引擎】

- **原来**：值轴刻度数量由绘图区尺寸自动推——1280×720 画布上两根柱子会长出十来条刻度线，而数据标签已经把数字标在柱顶，刻度是纯噪音。
- **现在**：有数据标签且类目 ≤4 → **整条值轴隐藏**；其余情况按「好读步长」（1/2/2.5/5/10 × 10^k）给 3~5 条刻度。
- **验收**：小类目数据页看不到 Y 轴刻度标签；大类目页刻度是 0/2/4/6/8 这类整齐数字。

### 3. 深红字压在深红柱子上（数据标签不可读）【已提交】

- **原来**：数据标签用系列色画在柱子上，深色系列 = 同色系字压同色系柱。
- **现在**：数据标签一律用正文色/次要色；另加一道可读性门——标签色与底色对比 <3:1 时**干脆不打标签**；打标签时关闭网格线；单系列或只有两个类目时不画图例。
- **验收**：任何数据页的标签都能读；不会出现「标签贴着柱子边且颜色接近」。

### 4. 色彩对比度爆炸（满屏高饱和深红 + 同色系暗红柱）【已提交】

- **原来**：色板只在「角色层」校验（主色/强调色），落到具体承载面（深色面板上的深色字）就失控。
- **现在**：三道闸
  1. **色板级**：大面积单色相占比 >30% 时饱和压到 ≤0.35；正文对比 <4.5:1（大字 <3:1）时调明度；同色相并置明度差 <0.15 时强制拉开。**色相一律保留**（品牌识别度靠色相）。
  2. **图表标签级**：见上条。
  3. **节点级**：按「元素自身填充 > 当前面板 > 页面底色」取真实承载面判对比度，只改文字色。
- **验收**：3 份真实材料各出一册，`deckQualityReport` 的 `palette.minContrast` ≥4.5、`minDeltaLstar` ≥0.15。
- **注意**：风格预览图与成品色值会有偏差，方向是「更亮 / 更淡」，色相不变——这是预期行为，不是 bug。

### 5. 中文标题折行溢出【已提交】

- **原来**：远档 `display` 96pt / `hero` 76pt（拉丁惯例）。汉字是满宽字，96pt 在 1280 宽画布上一行只放得下 9 个字，「深圳：一座仍在生长的城市」这种正常标题必然折行并溢出。
- **现在**：远档 `display` 60 / `hero` 54，近档 46 / 42，整条阶梯保持单调。
- **验收**：12 字以内的标题一行排下、不溢出、不被压扁。

### 6. 每份 deck 字号各漂各的【已提交】

- **原来**：风格卡也提取字号，同一场景下不同风格图给出不同阶梯。
- **现在**：字号完全归场景表，风格卡的 `typography.sizes / typeScale` 运行时忽略（老风格卡不报错，只是不生效）。

### 7. 进度卡把「还没落的页」算成已完成【已提交】

- **原来**：落页按完成顺序发生（第 2 页可能先于第 1 页落定），但卡面按「前 doneCount 页已完成」推断 → 第 1 页还在排，卡片已把 1/2/3 全打勾。
- **现在**：网关下发「已落定页号集合」，卡面按集合打勾；老载荷（无页号集合）回落到旧口径。
- **验收**：故意让首页排版变慢（或大页数 deck），观察勾选顺序应与实际落页顺序一致，不会给「还在排」的页提前打勾。

### 8. 布局代理说明书有两套语法【已提交】

- **原来**：`layout-tree-skill` + `layout-tree-v2-skill` 两份说明书并存，代理每次都读两遍，把工具轮次烧在「两种语法都对」的歧义上。
- **现在**：v2 是唯一写入语法；`SKILL.md` 不再手写，由 `docs/slides-layout-tree-spec.zh-CN.md`（权威正文）+ 各 agent 的 `appendix.md` 生成，CI 里 `--check` 防漂移。
- **自查**：`node scripts/render-layout-skills.mjs --check` 应输出「生成物与权威正文一致」。

### 9. 每次生成都压大纲、一压好几分钟【待落库】

- **原来**：整册草稿按 6 页一批丢给 LLM 压缩，1~4 批、每批几十秒。
- **现在**：压缩改成**代码**（`slides-condense.ts`，0 批 LLM、0.1ms 级）；planner 提示词在源头就把字写短；字数/事实/form 合法性由代码校验，不通过只把出错页（≤4 页）打回 `slides-editor` 做页级修复，最多 2 轮。
- **验收**：同一份材料生成时长显著下降；`subagent_invocations` 里不再出现 `task='演示文稿压缩编排'`。

## 三、优化与新能力

### 1. 场景体系（静默判断）【已提交】

| 指令片段 | 场景 | 距离 | 密度 | 正文最小 |
|---|---|---|---|---|
| 「给投资人做一轮路演」 | fundraising | 远 | 密 | 16pt |
| 「周一内部周会复盘」 | internal-review | 远 | 标准 | 16pt |
| 「产品发布会演讲」 | keynote | 远 | 疏 | 16pt |
| 「新人入职培训」 | training | 近 | 标准 | 14pt |
| 「打印出来尽调研读」 | reading | 近 | 密 | 14pt |

判不出来落 `internal-review`（最保守档），不猜极端值。场景写进 deck 元数据，界面上不展示。

### 2. 结构指标与质量报告【已提交】

`page-structure.ts` 只测不改：主角面积、留白率、对齐轴、行长度（measure）、字号档数。
`quality-report.ts` 出一册 deck 的六个数：最小字号、低于下限的文字块数、最低正文对比度、同色相最小 ΔL\*、超预算页数、组件种类数。**这张表是验收依据，不再靠"看起来好点了"。**

### 3. 排版手艺常量【已提交】

16px 间距网格（=12pt 整数倍）、正文 ≤22 字/行、同页字号档跨度 2~4 档、主角面积占版心 35%~65%。

### 4. 编排与并发【待落库】

- 三池并发：slides 16 / default 4 / background 2，`slides-editor` 挪进 background 池（实测影子压缩曾吃掉约 29% 的布局时间）；
- 页级窗口 `NXCORE_SLIDES_DECK_CONCURRENCY`（缺省 16）：改造前硬编码 8，15 页册要多等一整轮单页耗时；
- 落页改「占位页 + 按完成顺序落页」，审页在落页过程中流水线开跑；
- 风格阶段预热：草稿落文档即后台生图，用户秒确认不再触发重复生图竞态；
- 「layouter 自审回投」取代独立 `slides-reviewer` 派发：把该页渲染图直接投回布局代理，让它看着成品改；
- v3 骨架库起步（5 个骨架 + 打分选骨架，**尚未接线**）。

## 四、重点测试项（新功能）

1. **字号体系**：投影场合（路演/发布会/周会）出稿最大字号明显变小、正文更大；不应出现一页 5 种以上的字号档。
2. **颜色**：深色主题风格卡（红/蓝/紫）出稿，检查每页文字与所在底色能读；不再出现「同色系字压同色系块」。
3. **图表页**：小类目（2~4 类）数据页应无 Y 轴刻度数字；大类目页刻度整齐；数据标签颜色为正文色。
4. **标题溢出**：让 planner 出 10~14 字中文标题，检查一行排下、不折行溢出。
5. **风格卡兼容**：用旧风格卡（带 sizes 字段）走一遍，不应报错、只是字号不再跟风格卡走。
6. **进度卡**：大册（15 页以上）生成时观察勾选顺序，与实际落页顺序一致（不会给待定页打勾）。
7. **说明书一致性**：改网关后跑 `node scripts/render-layout-skills.mjs --check` 应为 ok。

## 五、回归项（必测）

1. 老 deck 的**编辑**路径（「把第 3 页标题改大」）行为不变；注意旧 deck 重新编译时字号会按新阶梯走，属预期。
2. 风格卡三选一、效果文案、演示页照常。
3. 配图流程（过目卡 / 重生成 / 打回 / 确认落页）照常。
4. Word / Excel 生成不受影响。
5. 生成中途取消 / 失败后重试：草稿保留，重试可复用已完成页。

## 六、已知边界与风险（测试时不要当 bug 提）

1. **引擎产物需重新 build**：只更新网关不重建 `apps/slides/out` 时，值轴刻度与讲稿不会变。
2. **色彩偏差**：色板按「色相继承 + L/S 重算」处理，成品色值与风格预览图有可解释偏差（更亮/更淡）。
3. **研读场景的 95 字/页偏紧**：文档式长册（尽调报告）可能显得太空，是否上调仍待产品拍板。
4. **v1 旧布局树与表格单元格配色未接承载面守门**（表格表头 fill + 反白字是成对写死的），属既有边界。
5. **页级并发一致性**：`agents/slides-layouter/agent.yaml` 的 `policy.maxConcurrency` 已随本批提到 16。若后续把 `NXCORE_SLIDES_DECK_CONCURRENCY` 配得比它更大，超出部分会被单代理限额秒拒 → 落兜底页。已在 `tests/subagent-pools.test.ts` 加断言守卫（该用例随下一批落地）。
6. **大册兜底告警属正常提示**：`warnings` 里的「已用 v2 兜底页」「保留占位页」「降档兜底」是确定性兜底，不中断整册；只有过半页取不到布局树才会整册报可重试失败（`slides_layout_agents_unavailable`）。

## 七、开发自查入口

1. `agents/` 或说明书有改动 → **重启网关**再验证。
2. 指标报告：按 `deckQualityReport` 看 `minFontPt` / `bodyFontPt` / `palette.minContrast` / `palette.minDeltaLstar` / 超预算页数 / 组件种类数。
3. sqlite `subagent_invocations`：一次 generate 应每页一条 `slides-layouter`（`input` 含 deckToken/pageIndex）；【待落库】后不应再出现整册压缩批次的记录。
4. sqlite `slides_storyboards`：`report.passed / errors / warnings`、`storyboard.pages[0].form`。
5. sqlite `slides_style_sessions`：`stage`、`generation`（验证风格预热不重复生图）。
6. 渲染抽查：soffice 默认 profile 转 pdf → sips 转 png（不用 pdftoppm）。
7. 新增/变更环境变量（【待落库】批）：

| 变量 | 缺省 | 作用 |
|---|---|---|
| `NXCORE_SUBAGENT_SLIDES_MAX_CONCURRENT` | 16 | slides 池 |
| `NXCORE_SUBAGENT_DEFAULT_MAX_CONCURRENT` | 4 | 交互链路池 |
| `NXCORE_SUBAGENT_BACKGROUND_MAX_CONCURRENT` | 2 | 影子作业池 |
| `NXCORE_SLIDES_DECK_CONCURRENCY` | 16 | 单册页级窗口 |
| `NXCORE_SUBAGENT_SLIDES_REASONING` | 未设 | slides-* 推理档位（非法值启动即报错） |
| `NXCORE_SUBAGENT_MAX_CONCURRENT` | **22（原 8）** | 全池总上限 |

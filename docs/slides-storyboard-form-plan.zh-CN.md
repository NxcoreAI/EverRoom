# 大纲生成方案 v1：用"内容形态"替代"版式选择"

状态：方案待评审 · 2026-10-21
范围：只改 `slides-editor`（大纲/storyboard）这一层，以及 `checkStoryboard` 的校验口径。不动 `slides-styler`、不动布局语法、不动渲染引擎。

## 0. 一句话

大纲不再写"这页用哪套版式"，改写"这页在论证什么"。版式由代码从内容形态推出来。

## 1. 为什么要改

三件事叠在一起，让产出必然收敛到最没特点的那个版式：

1. 大纲的输出里有一个"版式"字段，六选一。可枚举的东西，模型的偏好来自训练数据的频率，频率最高的必然最通用、最没特点。
2. 六种版式的失败门槛不一样。最有表现力的三种要求最多（必须有满版图、必须有大字、必须有图配标题），最没特点的那种（严格等分网格）没有任何要求。
3. 代码里有两处"写不出来就默认成最没特点的那个"。

结果：**越有表现力的版式风险越高，越平庸的版式越安全。** 这是激励问题，不是提示词问题。

## 2. 核心改动

### 2.1 删掉版式字段，换成内容形态

大纲每页现在输出：`role / density / composition / emphasis / intent / takeaway / copy / data / visual / dropped`

改成：`role / density / form / units / weight / emphasis / intent / takeaway / copy / data / visual / dropped`

| 字段 | 动作 | 说明 |
|---|---|---|
| `composition` | **删** | 版式名不再由大纲产出，也不能由大纲产出 |
| `form` | **加** | 这页的证据形态，九选一（见 §2.2） |
| `units` | **加** | 这页有几个单元（1~5）。对照的"方"、序列的"步"、拆解的"块" |
| `weight` | **加** | 这页在全册里的分量：light / medium / heavy |
| `emphasis` | 收窄 | 语义改为"这页的主角用什么承载"，且必须与 `form` 相容 |
| `density` | 保留 | 内容量，校验预算按 `form` 给（见 §2.3） |

关键区别，也是这个方案能不能成立的前提：

> **`form` 是对内容的判断，对错有客观答案**——这页到底是不是"两方对照"，可以查、可以打回重写。
> **版式名是对审美的偏好，没有客观答案**——说"这页该用海报式"无法被证伪，所以模型只能按频率猜。

所以这个改动不是"换一个更小的菜单"，是把一个无客观答案的判断，换成一个有客观答案的判断。

### 2.2 内容形态词表（九类）

每一类的判定条件写在括号里，必须能由校验器判定，不能是口味。

| form | 判定条件 | 骨架 | 引擎构图 |
|---|---|---|---|
| `single-fact` | 只有 1 个数字或 1 个结论要成立，units=1 | 大数字 + 极小注脚 | hero-data |
| `contrast` | 有 2 方以上互相对立的属性，units=2~4 | 并置，权重 1.4:1 或 1:1，中缝分隔 | editorial |
| `sequence` | 单元之间有先后或因果，顺序不可换，units=3~5 | 横向轨道串节点 | editorial |
| `hierarchy` | 单元之间有层级或包含关系，units=3~5 | 逐层加宽 / 嵌套 | editorial |
| `breakdown` | 3~4 个并列等权单元，无先后 | 并列块，可不等权 | editorial |
| `image-led` | 页面主体是一个画面（visual.kind ≠ none；图来自素材或生成都一样） | 出血图 + 少量文字 | immersive |
| `quotation` | 原文引用，必须保留原话 | 大留白 + 一行字 + 署名 | poster |
| `table` | ≥3 行的对照表 | 表格 + 一句结论 | hero-data |
| `light-page` | 内容量低于最低单元数（role=cover/section/closing，或 units≤1 且无数字） | 一句话 + 大留白 + 满版底色 | chapter / poster |

两条附带规则：

0. **`swiss` 的语义变了**：在 v2 引擎里它只表示「没有额外硬约束」，不再表示「严格等分网格」。本方案下它只会从两种事实推出来——**无图可用的结构页**、以及**表格页**。也就是说：落在 swiss 不是「选了保守选项」，而是「这页没有图」。这暴露了真正的表达力上限在**素材质量**，不在版式选择。

1. **`swiss` 从默认变成窄口**：只有 `breakdown` 且无图且各单元严格等权时，才落到等分网格。它不再是任何页面的兜底。
2. **`emphasis` 必须与 `form` 相容**：`single-fact` 不允许配 `table`；`image-led` 不允许配 `number`；`quotation` 必须是 `quote`。不相容按缺陷处理。

### 2.3 预算按形态给

现在的事实上限是全局的（facts ≤3、页面文案 ≤60/80 字）。这会**卡死**序列和拆解这两类页——5 步的流程写不进 3 条事实里。所以预算必须跟着形态走：

| form | units | facts 上限 | 页面文案预算 |
|---|---|---|---|
| single-fact | 1 | 2 | 60 |
| contrast | 2~4 | 4 | 100 |
| sequence | 3~5 | 5 | 110 |
| hierarchy | 3~5 | 5 | 110 |
| breakdown | 3~4 | 4 | 100 |
| image-led | 1~2 | 2 | 50 |
| quotation | 1 | 1 | 60 |
| table | 3~8 行 | 3（只留结论） | 60 |
| light-page | 1 | 0 | 40 |

`message ≤24 字`、`takeaway ≤22 字`、`intent 10~60 字`、`speakerNotes 60~260 字` 不变。

## 3. 声明义务：替代原来的硬约束闸门

原来"某种版式必须有大图/大字"的约束，本质是给表达力加罚。现在约束改成：**你声明了什么，就必须真的给出什么。** 五条，全部可在内容层判定：

| 声明 | 必须 | 否则 |
|---|---|---|
| `contrast` | units ≥2，且两方有对立维度 | 缺陷，回上游重写该页 |
| `sequence` | 单元文案里有先后词或序号 | 可疑，返工一次 |
| `image-led` | `visual.kind ≠ none`（不看图从哪来） | 缺陷 |
| `table` | `data.table` 存在且 ≥3 行 | 缺陷 |
| `single-fact` | facts ≤2 | 缺陷 |

这些约束由**内容**承担，不由**版式选择**承担。所以表现力不再被加罚——想用大图页，前提只是"你真的有图"，而不是"你敢赌"。

## 4. 防止新的吸引子

换掉版式菜单之后，最容易被滥用的是 `breakdown`（并列块最好写）。三条分布约束，防止它变成新的安全牌：

1. 一册里 `breakdown` 占比 ≤50%。
2. ≥8 页的册至少出现 3 种 `form`。
3. `light-page` 在**内容页**里的占比 ≤15%（封面/章节/收尾本来就是轻的，不计入；内容页少于 3 页时不启用这条）。

如果一册里有大半页都是 `breakdown`，那不是版式问题，是**大纲本身在把结构不同的内容压成清单**，该回上游重写。

## 5. 全册节奏

`weight`（light / medium / heavy）替代原来"相邻页版式不得相同"那条弱约束。四条可判定规则（前两条是 error，后两条是 warning——结构问题拦死，节奏问题只提示）：

1. ≥8 页的册至少有 1 页 heavy。
2. 不得连续 3 页同为 light。
3. 封面与收尾不得同为 heavy。
4. heavy 页的位置落在全册 55%~75% 区间。

## 6. 返工与失败

- 每页最多 1 次内容返工，返工时把具体缺陷（哪一条声明义务没满足）带回去只改这一页。触发条件：校验错误里带 `形态：` 前缀的那些（网关按前缀只针对形态类缺陷返工，不整册重排）。
- 仍失败 → 该页落 `light-page`，记一条内部 warning，不阻塞整册，用户侧不显示技术提示。
- **删除两条"写不出来就默认"的路径**：大纲规范化时不再补默认版式；兜底页不再按角色推默认版式。

## 7. 版式层的自查自修（不改语法，只加判定）

生成后的页面按六条"能判定的坏"自查，不合格的自己重排，不问用户：

1. 文字溢出或被裁断。
2. 文字与底色对比度不足。
3. 多块等宽等高（等分 = 无主次）。
4. 最大那块没有明显大于第二块（主角不成立）。
5. 相邻两页结构几乎一样。
6. 形态与几何不符：声明了 `contrast`，但两块内容的量级差超过 2 倍。

第 6 条是唯一能在"意义层"自动查的一条，因为形态是声明的、几何是可测的，两者可以对照。

## 8. 明确不做

1. 不做多候选让用户挑版式。
2. 不让用户看样张、不要求回头二次确认。
3. 不把坏页面图片喂给页面审阅环节（它现在的判定纪律是"指得出位置 + 不确定放过"，喂图片会破坏这两条）。
4. 不给版式层做风格菜单（风格可以菜单，因为那是用户的偏好；版式不给，因为那是内容的领域）。
5. 不让自动检查判"好不好看"，只判"合不合格"。审美一旦变成分数，模型就会学着骗分。

## 9. 验收标准

1. 大纲输出里不再出现版式名（schema 断言失败即视为回退）。
2. 一册里 `light-page` 占比 ≤15%，返工率 <20%。
3. **同一份草稿 + 同一风格，两次生成的内容形态序列一致率 >80%**。形态由内容定，所以这个数字应该高；它是"版式不再靠猜"最直接的证据。
4. 全册 `weight` 曲线满足 §5 四条规则。
5. 盲评里"信息层级"一题均分提升，"有没有明确视觉意图"一题不下降。

## 10. 落地顺序

**P0（先做，1~2 天）**
- 大纲 schema：删 `composition`，加 `form / units / weight`。
- `agents/slides-editor/SYSTEM.md`：删掉六种版式的枚举段落，换成 §2.2 的形态判定条件 + §2.3 的预算表 + §3 的声明义务。
- 代码侧：形态 → 骨架 → 引擎构图的映射表（九行）；删掉两处默认版式。
- 校验：预算改按形态给；加 §3 五条声明义务；`emphasis` 与 `form` 相容性。

**P1**
- §4 分布约束、§5 节奏规则、§6 返工策略。
- §7 的第 6 条（形态与几何不符）。

**P2**
- 离线标定：把已有人工认可的好页面、明确不要的坏页面，编码成规则与提示里的约束。

## 11. 风险

1. **形态判定被模型强行套用**：某一页内容其实模糊，硬塞成 `contrast`。缓解：§3 的声明义务会把它查出来，回上游改。
2. **`breakdown` 变成新的安全牌**：缓解 §4 分布约束。
3. **`light-page` 被当成省事出口**：缓解 §4 的 15% 上限 + §6 的返工记录会让它出现在统计里。
4. **形态词表本身不够用**：九类是起步集，先跑一册真实素材看覆盖率；缺的形态补进表，不要把不认识的页塞进 `breakdown`。

## 13. 更正：生图不是卡点（2026-10-21 晚）

上一节写的「表达力上限卡在素材」是错的。agent 确实可以调生图模型，所以「没有真实素材就排不出满版图」这个说法不成立。更正如下。

**生图能解决的**：有没有图可排。引擎要求 `immersive` 必须有出血图，生成一张就满足了。

**生图不能解决的**：

1. **图当证据**。`evidence-image` 这个形态的定义是「图本身就是证据」——现场照片、产品实拍、数据快照。放一张生成图，等于伪造证据。这不是审美问题，是事实问题。
2. **成本与延迟**。一册 20 页塞 10 张生成图，生图时间与费用都要翻倍，而且生图有失败率、要 QC、要重试。
3. **一册要像一套**。多张生成图必须同明暗、同色系、同处理方式，否则一眼看出是拼的。这条最难，也是 AI 配图最常翻车的地方（不是画得不好，是不成套）。

**因此的改动**

1. 把原来的「图为主证」拆成两个形态：
   - `evidence-image`（真实照片作证据）：`visual.kind` 必须是 `material`，**写 `generated` 直接判错**——证据页放生成图就是伪造证据。
   - `illustration`（生成图作氛围）：可以 `material` 也可以 `generated`，用于撑气氛、把抽象概念具象化。两者排法相同，区别只在图的来源和它要不要背结论。
2. 加一条全册配额：**用生成图的页不得超过三分之一**（≥6 页的册生效）。生图有成本和一致性代价，不能当「没素材」的通用解法。
3. 布局代理侧不变：`illustration` 与 `evidence-image` 推导出同一个构图，它不需要知道图从哪来。

**所以真正的限制是什么**

不是「有没有图」，而是三件事：**图要不要背结论**（决定用真素材还是生成图）、**一册能生成几张**（配额与成本）、**这些图成不成套**（一致性）。前两件已经变成可判定的规则，第三件目前只能靠"同色系同处理"的提示词约束，还没有闸门——这是 P1 该补的。

原来那句应该改成：表达力上限卡在**图的来源是否可信**和**图的一致性**，不在有没有图。

## 14. 再更正：形态判定不看图的来源（2026-10-21 晚，最终）

第 13 节把「图为主证」拆成「真实照片作证据」和「生成图作氛围」两个形态，并给生成图加了三分之一配额。**这个拆分撤回。**

理由：形态是对内容的判断，不是对素材来源的判断。同一页「画面为主、文字做注释」，图是拍的还是生成的不改变这个判断。按来源拆形态，等于让素材管理的问题渗进内容分类里，还多出两条要维护的规则。

**现在的做法**

1. 只有一个形态：`image-led`（图为主视觉）——页面主体是一个画面，文字只做结论和注释。
2. 判定条件只有一条：`visual.kind ≠ none`。不看是 `material` 还是 `generated`。
3. 没有生成图配额。素材库里有的先用，没有再生成——这是取材顺序，不是校验规则。
4. `visual.kind` 仍然要写（下游生图环节需要它），但它不参与任何验收判定。

**被放弃的两条规则（记录在此以免重新发明）**

- 「证据页不许用生成图」：产品上不区分，撤回。
- 「生成图不超过三分之一」：这是成本策略，不是内容判定。若之后生图费用或一致性真的成为问题，应该在生图环节按预算控制，不要绕回来改内容形态。

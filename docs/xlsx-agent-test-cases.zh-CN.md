# Excel Agent 编辑能力 · 可执行测试用例规格

> 版本：v1（2026-10-31）｜分支：`feat/doc-office`
> 关联：`xlsx-agent-test-prompts.md`（提示词手册）、`docs/xlsx-agent-operation-coverage.zh-CN.md`（Ribbon 入口覆盖审计）、`docs/xlsx-agent-editing-implementation.zh-CN.md`（架构与错误模型）
>
> 分工：提示词手册回答「能问什么」；**本文件回答「跑完算不算通过、怎么验、失败长什么样」**。
> 每条用例都有：编号 / 优先级 / 前置 / 提示词 / 期望 agent 行为（工具与 op）/ 期望文件效果（可脚本断言）/ 判定标准 / 失败信号。

---

## 0. 使用方式

0. 只想先跑一轮核心验收：看 `docs/xlsx-agent-top20-test-cases.zh-CN.md`（20 条主流程，12 条是行/列/工作表级真实结构改动）。
   要「提示词 + 怎么算通过」合在一页：看 `docs/xlsx-agent-test-cases-expected.zh-CN.md`（逐条给提示词、预期结果、不通过表现，含数值基线）。
   要「能直接粘贴的提示词」：看 `docs/xlsx-agent-test-prompts-by-case.zh-CN.md`（与本文件编号一一对应，含造数与环境自检话术）。
1. 过一遍 §1 环境前置清单（全绿才开跑）。
2. 按分组跑：先 P0（核心链路），再 P1（进阶能力），最后 P2（体验与性能）。
3. 每条用例用 §8 的 `openpyxl` 断言模板核验「期望文件效果」，不靠肉眼扫表。
4. 结果记进 `docs/xlsx-agent-test-case-tracker.xlsx`（PASS / PARTIAL / FAIL / HARD FAIL / BLOCKED + 证据）。
5. 每轮回归至少跑完 A / B / H / E 四组 P0 用例（约 25 条，1.5 小时内可完成）。

## 1. 环境前置

| # | 检查项 | 通过标准 |
|---|---|---|
| P-1 | 桌面端已重启，载入最新 embed runtime | 会话工具表出现 `sheets_agent_read` / `sheets_agent_edit` |
| P-2 | 文件库工具可用 | `file_search` 能按文件名搜到 `财务报表_2026年10月.xlsx` 并返回 `kind: excel` + `fileId` |
| P-3 | 可观测性就绪 | 开发者工具的 tool 调用日志可见（判定要看真实调用的 op 名） |
| P-4 | 版本历史可用 | 产物详情能看版本号与回退入口（判定版本回填用） |
| P-5 | 干净基线 | 每轮开始前把 FIX-1 回退到基线版本 v0 |

**工具词汇表核对**（不需要读代码，让 agent 复述即可）：

- 读（11）：`get_workbook_context` / `read_range` / `read_cells` / `read_formats` / `read_sheet_features` / `find_cells` / `aggregate_range` / `select_range` / `trace_precedents` / `trace_dependents` / `load_guide`
- 写（唯一通道）：`propose_operations({operations, summary})`
- 调用预算：`calls` 1–50 条/次；普通批 ≤2000 个展开单元格；范围级 op（`fill_range`/`copy_range`/`convert_to_values`/`clear_range`/`find_replace`/`format_range`）单条 ≤20 万单元格；数据工具 op（`remove_duplicates`/`text_to_columns`/`consolidate`）共用 2 万预算
- 批次约束：结构类 op（含 `remove_duplicates`）不能与非结构 op 同批
- 不支持：`dryRun`（Excel 是渲染层即时 apply）、打开密码、公式求值、切片器/日程表、快速填充

## 2. 测试数据（Fixture）

> 文件位置：`test/fixtures/xlsx-agent/`（同目录 README 有各 fixture 的基线数值与 FIX-3~FIX-5 造数命令）。

| ID | 文件 | 用途 | 特征 |
|---|---|---|---|
| FIX-1 | `财务报表_2026年10月.xlsx` | 主用例 | 3 个工作表：`薪酬明细`（A1:M17，10 名员工 + 合计行，含嵌套 IF 个税公式与跨列表算）、`部门汇总`（COUNTIF/SUMIF 跨表引用）、`编制说明`（文本说明 10 行） |
| FIX-2 | `销售明细_1万行.xlsx`（需生成） | 性能/上限 | 单表 1 万行 × 8 列，含公式列，用于 `fill_range` 与批预算测试 |
| FIX-3 | `加密.xlsx`（CFB 魔数）/ `损坏.xlsx` / `超大.xlsx`（>100MB） | 负向 | 错误码 `encrypted` / `open_failed` / 拒绝 |
| FIX-4 | `旧版.xls` / `数据.csv` | 类型路由 | 期望 `not_xlsx`，提示另存为 `.xlsx` |
| FIX-5 | FIX-1 的副本 `财务报表_只读.png`… 实际为只读打开的副本 | 会话 | 可见只读实例 |

> FIX-1 现成可用（仓库根目录已有该文件，3 个工作表、公式齐全、含跨表 SUMIF），是这批用例的默认锚点。每轮测试前复制一份作为「测试副本」，避免污染原始文件。

## 3. 判定口径

| 结论 | 定义 | 处理 |
|---|---|---|
| **PASS** | 文件效果与「期望文件效果」全部断言通过，且未改动目标范围外内容，报告如实 | 记通过 |
| **PARTIAL** | 主效果达成，但有边界瑕疵（多改了格式、多一次无谓 op、坐标写错但值对、跳过 read 直接写） | 记 minor 缺陷 |
| **FAIL** | 效果不符：写成死值而非公式、数据错行错列、`#REF!`、格式未生效、版本未回填 | 记 major 缺陷 |
| **HARD FAIL** | 谎报成功（说有改动但字节没变）、越权改动范围外内容、绕过只读/脏闸门、静默覆盖用户未保存输入 | 记 blocker，当轮停止 |
| **BLOCKED** | 环境或工具缺失、fixture 不可用 | 记环境问题，不计入通过率 |

通过率口径：`PASS 数 / (总用例数 − BLOCKED 数)`；P0 用例通过率必须 100% 才允许发版。

## 4. A 组：读取与理解（XL-R）

### XL-R-01 工作簿总览
- 优先级：P0
- 前置：FIX-1 已入库，未打开或已打开均可
- 提示词：`看一下这份财务报表的结构：有几个工作表、每个表大概多少行多少列、现在选中哪个表。`
- 期望行为：`sheets_agent_read` → 底层 `get_workbook_context`；不逐格 `read_range` 全表
- 期望效果：报出 3 个工作表（`薪酬明细` / `部门汇总` / `编制说明`），`薪酬明细` 数据范围到 M17 附近（允许报 A1:M17 或 A4:M17 两种口径），不虚构第 4 个表
- 判定标准：工作表名与数量 100% 正确；行列数与 openpyxl `ws.dimensions` 一致（±1 行）；单次调用 ≤3 个
- 失败信号：漏报 `编制说明`；把 `max_row` 当数据行数（把合计行算成员工）；读整表导致上下文爆掉

### XL-R-02 精确区域读取
- 优先级：P0
- 前置：同 R-01
- 提示词：`把「薪酬明细」前 5 行的姓名、部门、基本工资、实发合计读出来，用紧凑表格给我。`
- 期望行为：`read_range` 两次（或用一次区域 + 列过滤），区域精确到 A5:A9 / C5:C9 / E5:E9 / M5:M9
- 期望效果：5 行数据与文件一致（张伟/技术部/18000/实发按公式结果）；`实发合计` 给的是计算结果而非 `=H5-I5-K5-L5` 字符串
- 判定标准：数值逐个相等（允许 2 位小数）；报表不串行（李娜不被写成市场部）
- 失败信号：把公式串原样贴给用户；读回 `None` 却说"空";行列错位一格

### XL-R-03 稀疏单格读取
- 优先级：P1
- 提示词：`「编制说明」第 3 条和第 6 条分别写了什么？顺便看一下 A1 是什么。`
- 期望行为：`read_cells`（按单元格地址集合读），而不是整表 `read_range`
- 期望效果：准确回读两条说明原文（社保 22.5% 那条 / 实发合计公式那条），A1 = `编制说明`
- 判定标准：文本一字不差（允许标点归一）；调用次数 ≤2
- 失败信号：编造说明内容；把整张 `编制说明` 读一遍再说

### XL-R-04 统计聚合（不要逐格加总）
- 优先级：P0
- 提示词：`「薪酬明细」里技术部的实发合计总额是多少？全公司个税最高的是谁、多少钱？`
- 期望行为：`aggregate_range`（求和/最大值）或读区域后计算；不逐格 10 次 `read_cells`
- 期望效果：技术部实发合计 = 张伟+李娜+王强+刘洋 四行 M 列之和；个税最高为刘洋（K8），金额与文件计算结果一致
- 判定标准：两个数值与 openpyxl 计算值误差 ≤0.01；能说明口径（含/不含合计行）
- 失败信号：把合计行重复加进去（金额约翻倍）；给出的数字在文件里找不到

### XL-R-05 跨表查找
- 优先级：P1
- 提示词：`在整个工作簿里找出所有出现「技术部」的单元格，按工作表分组列出来。`
- 期望行为：`find_cells`（必要时按表分别查）
- 期望效果：命中 `薪酬明细` C5:C8 四个 + `部门汇总` A4 一个（共 5 处，允许因合并/标题差异 ±1）
- 判定标准：坐标用 A1 记法且带工作表名；无漏项、无假阳性
- 失败信号：只查当前活动表；把 `技术部` 子串误命中到别处

### XL-R-06 格式读取
- 优先级：P2
- 提示词：`「薪酬明细」里金额列现在用的是什么数字格式？表头行是加粗的吗？`
- 期望行为：`read_formats`
- 期望效果：如实报出格式串（如 `#,##0.00` 或 `General`）、表头加粗与否
- 判定标准：与 `openpyxl` 读到的 `number_format` / `font.bold` 一致
- 失败信号：凭经验猜"应该是千分位"；答"看不出"

### XL-R-07 公式依赖审计
- 优先级：P0
- 提示词：`「薪酬明细」M5 这个格的公式引用了哪些单元格？反过来，E5 被哪些公式用到？`
- 期望行为：`trace_precedents`（M5 → H5/I5/K5/L5）+ `trace_dependents`（E5 → H5/I5/M5）
- 期望效果：前置引用链完整（M5←H5,I5,K5,L5；H5←E5,F5,G5；I5←E5）；从属关系至少包含 H5、I5、M5
- 判定标准：引用集合与真实公式一致；坐标带表名
- 失败信号：只报一层且漏项；把 `M5` 依赖说成只依赖 H5

### XL-R-08 特性读取（条件格式/验证/备注）
- 优先级：P1
- 前置：先跑 F-06、D-01、V-06 造出条件格式、数据验证、备注
- 提示词：`这份表现在有哪些条件格式、数据验证和批注？分别在哪张表哪些区域？`
- 期望行为：`read_sheet_features`
- 期望效果：三类对象全部列出，区域与先前写入的一致
- 判定标准：类型/区域/规则数三项核对通过；不清空已有规则
- 失败信号：答"没有"；把条件格式和表格样式混为一谈

## 5. B 组：内容写入与公式（XL-W）

### XL-W-01 单格改值 + 全链重算
- 优先级：P0
- 前置：FIX-1 基线，文件可编辑
- 提示词：`把「薪酬明细」张伟的基本工资从 18000 改成 20000，其他自动算的列跟着更新。`
- 期望行为：先 `read_range` 确认行号 → `propose_operations([set_cell E5])`；不手算下游列
- 期望效果：E5=20000；H5/I5/J5/K5/M5 仍是公式（`data_type == 'f'`）且缓存值按新基数更新；`部门汇总` C4（技术部应发合计）随之变化
- 判定标准：只有 E5 的值变；下游全是公式；跨表 SUMIF 结果同步（误差 ≤0.01）；版本 +1
- 失败信号：把 H5/M5 写成算好的常量；误改 E6；`部门汇总` 没跟着变（说明存的是死值）

### XL-W-02 追加新行并沿用公式
- 优先级：P0
- 提示词：`在「薪酬明细」最后一名员工下面加一行：孙悦、技术部、数据工程师、基本工资 15000、绩效 3000、津贴 800，公式列照上面的写法。`
- 期望行为：`insert_rows`（若需保持合计行在最后）或直接写入第 15 行；公式列用 `set_formula` 或 `fill_range` 平移
- 期望效果：新行落在员工区最后一行（合计行之前），H/I/J/K/M 为公式且引用本行；合计行的 `SUM(E5:E14)` 范围扩到含新行
- 判定标准：公式相对引用正确（`=E15+F15+G15` 这一族）；合计行范围自动/显式扩到 E15；文本姓名为"孙悦"
- 失败信号：写进合计行位置覆盖合计；公式引用仍指向第 5 行；合计未含新行

### XL-W-03 批量公式填充
- 优先级：P0
- 提示词：`给「薪酬明细」新增一列「社保公积金(单位)」，按基本工资的 35% 计算，整列填满（含所有员工行），表头加粗。`
- 期望行为：`set_cell`(表头 N4) + `fill_range`(N5:N14, `=ROUND(E5*0.35,2)`) + `format_range`(N4 bold)；一条 `fill_range` 而不是 10 次 `set_formula`
- 期望效果：N4=`社保公积金(单位)`；N5:N14 全为公式且逐行平移；值 = 基本工资×0.35（两位小数）
- 判定标准：10 个单元格全为公式；数值误差 ≤0.01；op 数 ≤4；未改其他列
- 失败信号：逐格 10 次 `set_formula`（超预算且慢）；整列引用 `$E$5` 导致全列同值；写到 N15

### XL-W-04 区域一次性写入
- 优先级：P1
- 提示词：`在「编制说明」下面的空行追加一个 3 列的说明块：日期、修订人、修订内容，先填 3 行示例数据。`
- 期望行为：`set_range`（3×3 一次性写）
- 期望效果：目标区域 9 个单元格值与给定数据完全一致；未覆盖上方说明文字
- 判定标准：一个 op 完成；区域与内容行列对齐；纯文本不被识别成日期/数字类型错乱
- 失败信号：9 次 `set_cell`；日期被写成序列号且格式错误；覆盖原文

### XL-W-05 区域复制（公式平移）
- 优先级：P1
- 提示词：`把「薪酬明细」A4:M14 复制到新工作表「明细备份」，公式保持，公式里的引用指向备份表自己的数据。`
- 期望行为：`add_sheet` + `copy_range`（优先 `duplicate_sheet` 等价路径）
- 期望效果：新表 11 行 × 13 列内容一致；备份表 H5 公式为 `=E5+F5+G5`（指向自身而非 `薪酬明细!`）；原表未变
- 判定标准：抽查 5 个公式单元格，引用均为本表相对引用；数值一致
- 失败信号：复制成常量；公式仍引用 `薪酬明细!`；原表被改动

### XL-W-06 公式转数值
- 优先级：P1
- 提示词：`把「部门汇总」里的公式全部变成当前算出来的数值，公式清掉，格式保留。`
- 期望行为：`convert_to_values`（范围 b4:f9）
- 期望效果：B4:F9 `data_type` 从 `f` 变 `n`，数值等于转换前的缓存值；字体/数字格式不变
- 判定标准：值差异 ≤0.01；格式属性逐项相等；其他表不受影响
- 失败信号：转完值全 0/None（用了未重算的缓存）；格式丢失；把 `薪酬明细` 也转了

### XL-W-07 文本查找替换（不动公式）
- 优先级：P1
- 提示词：`把「薪酬明细」里所有「技术部」改成「研发部」，别动数字和公式。`
- 期望行为：`find_replace`（限定 C 列或整表范围）
- 期望效果：C5:C8 变"研发部"；E 列数值、H 列公式原样；`部门汇总` A4 若不在替换范围则仍是"技术部"（需在报告中说明这一不一致）
- 判定标准：只改文本单元格；公式与数值零改动；agent 主动提示跨表引用会失配
- 失败信号：公式里的 `"技术部"` 被替换导致结果变化而未说明；数字被当成文本替换匹配

### XL-W-08 区域清空（内容 vs 格式）
- 优先级：P2
- 提示词：`把「编制说明」第 8–10 条清空内容，但保留单元格格式。`
- 期望行为：`clear_range`（仅内容）
- 期望效果：A8:A10 为 `None`；字体/边框/数字格式保持
- 判定标准：内容清空、格式不变、上方内容未动
- 失败信号：把整表清空；连格式一起清掉（那是 `clear_formats` 的语义）

## 6. C 组：格式与数字格式（XL-F）

### XL-F-01 表头样式
- 优先级：P0
- 提示词：`「薪酬明细」第 4 行表头：加粗、浅灰底、居中、自动换行；列宽调到不溢出。`
- 期望行为：`format_range`(A4:M4, bold/fillColor/align/wrapText) + `set_col_width`
- 期望效果：A4:M4 `font.bold=True`、填充为浅灰、`horizontal='center'`、`wrap_text=True`；列宽增加（如 ≥12）
- 判定标准：13 个表头单元格全部生效；第 5 行数据行格式不变
- 失败信号：只改首个单元格（选区变成单格）；整表加粗；列宽没变

### XL-F-02 数字格式三件套
- 优先级：P0
- 提示词：`金额列用千分位两位小数；「社保公积金(个人)」用同样格式；标题下面的日期行改成 yyyy-mm-dd。`
- 期望行为：`format_range.numberFormat`（`#,##0.00` / `yyyy-mm-dd`）
- 期望效果：E:M 列 `number_format == '#,##0.00'`；底层值不变（仍是 18000，不是 "18,000.00" 字符串）
- 判定标准：格式串精确匹配；`data_type` 仍为数值；仅目标区域生效
- 失败信号：把值转成字符串；格式写成 `0.00` 丢千分位；整表套日期格式

### XL-F-03 财务会计格式（负数/零值）
- 优先级：P1
- 提示词：`「实发合计」列用会计格式：人民币符号、负数红色括号、零显示成短横线。`

- 期望效果：绩效更新 → 应发/个税/实发/部门汇总全部联动；图表存在；两表页面设置正确
- 判定标准：跨表联动正确（误差 ≤0.01）；图表与页面设置落盘
- 失败信号：只改明细不重算；图表丢失；页面设置只应用到一张表

### XL-E2E-03 公式审计与纠错
- 优先级：P1
- 提示词：`帮我审一下这张表的公式：个税公式是不是对的（2026 年 10 月按月度预扣，起征点 5000）、社保口径一致吗、有没有引用错行。给出问题清单并修好能确定的错误。`

- 判定标准：清单可核对；不臆造问题；修复项有前后对照
- 失败信号：泛泛而谈"公式看起来没问题"；乱改正确公式

### 14.1 断言模板（openpyxl）

```python
import hashlib, openpyxl

def sha256(p):
    return hashlib.sha256(open(p, 'rb').read()).hexdigest()

def load(p, formulas=True):
    # formulas=True 看公式与结构；data_only=True 看缓存计算结果
    return openpyxl.load_workbook(p, data_only=not formulas)

# 例：XL-W-01 —— 只有 E5 变，下游仍是公式
wf = load('财务报表_2026年10月.xlsx')          # 公式视角
ws = wf['薪酬明细']
assert ws['E5'].value == 20000
assert ws['H5'].value == '=E5+F5+G5'          # 公式还在
assert ws['M5'].value == '=H5-I5-K5-L5'
wv = load('财务报表_2026年10月.xlsx', formulas=False)   # 缓存值视角
assert abs(wv['薪酬明细']['M5'].value - 期望值) <= 0.01
```

> 注意：`data_only=True` 依赖文件里有缓存值；若保存链路没写缓存，应改为「用 Excel/LibreOffice 重算后再读」或只断言公式与结构。

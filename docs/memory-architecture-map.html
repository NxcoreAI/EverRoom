记忆架构剖面
与 Agent / LLM 边界

这个产品的"记忆"不是一个数据库，而是五层不同寿命的载体 + 三条写入链路 + 两条读取链路。 能"自己找记忆"的只有工具型 harness（13 个 Agent 身份）；其余九处模型调用都是一次性 提示词 → 输出，没有工具、没有会话、没有第二轮。

如何使用

六条横带 = 六层

自上而下：界面 → 桌面壳 → 网关编排 → 运行时 → 载体 → 模型

实线箭头是调用或写入（自上而下），虚线箭头是回读（自下而上）。

三种"看起来像记忆"的东西

  • 载体 真正落盘的东西：SQLite 表、hippo 库、pi 会话文件、对象库。
  • 代码 决定写什么、读什么的编排逻辑（无模型）。
  • Agent / LLM 唯一真正"产生理解"的两类。

一个反直觉的事实

长期记忆库没有独立进程、没有端口、也不外呼模型：它是网关进程内一层 node:sqlite，整理回合的 LLM 事实提取被代码硬关掉。

纵轴 = 信息寿命 · 横条 = 留存强度（衰减后剩余比例）· 每一层都有自己的写入者与读取者

# PPT（.pptx）Agent 修改能力测试用例

> 目的：验证 Agent 能否**仅凭自然语言提示词**，通过 `slides_read` / `slides_edit` 正确修改一份已打开的 PPT，并且结果可复核、可回滚。
>
> 适用版本：EverRoom `feat/doc-office`（genoffice 子模块 `everroom/host-agent-tools`）
> 编写时间：2026-11-05

---

## 一、被测能力与边界

Agent 修改 PPT 走的是**活文档通道**，不是「生成一份新 PPT」：

| 工具 | 作用 |
|---|---|
| `slides_read` | 读大纲 + 操作词汇表（`opVocabulary`）。**编辑前必调**：大纲里的元素 id 是定位唯一依据 |
| `slides_edit` | 一次事务提交 `ops[]`，原子生效；返回新大纲，可直接链式编辑 |
| `slides_draft` | 走子代理从零生成新 PPT（本套用例**不覆盖**，另测） |

硬性约束（写用例时据此判定）：

- 一次事务 **1~50 个 op**；
- `target.slide` **从 0 计**（界面上第 1 页 = `slide:0`）；
- 默认 `atomic`：任一 op 失败则整批不生效；`isolation:"per_op"` 可放开；
- `dryRun: true` 只校验不落盘；
- 元素 id 来自本页大纲；删除/新增元素后 id 会变，**每次编辑前重新 `slides_read`**；
- 编辑实时显示在打开视图上并自动保存，**版本链 +1**。

操作词汇共 63 个，分 6 组（`opVocabulary` 里每项自带签名）：

| 组 | 操作 |
|---|---|
| text | `setText` `setFont` `setParagraphFormat` |
| element | `deleteElement` `setFill` `setStroke` `setTransform` `setConnectorEndpoints` `flipElements` `setPictureSrcRect` `setPictureOpacity` `reorderElement` `groupElements` `ungroupElement` `setShapeGeometry` `setShapeAdjust` `setTextAnchor` `setTextBodyProps` `setEffects` `setLink` `setImageFill` |
| insert | `addElement` `addPicture` `replacePicture` `addTable` `addChart` `addSmartArt` `addMedia` `addModel3d` `pasteElements` |
| table | `setTableCell` `tableMerge` `tableStructure` `setTableRowHeight` `setTableCellAnchor` `setTableColWidth` `setTableStyle` `setChart` |
| slide | `deleteSlide` `duplicateSlide` `addBlankSlide` `addSlideWithLayout` `pasteSlide` `insertSlidePptx` `moveSlide` `setSlideLayout` `setBackground` `setHidden` `setTransition` `setAdvanceTime` `setAnimations` `setNotes` `addComment` `deleteComment` |
| deck | `setSlideSize` `findReplace` `applyHeaderFooter` `setSections` `applyTheme` `addSection` `renameSection` `removeSection` `moveSection` |

## 二、前置条件

### 2.1 测试文件

任选其一：

- **A. 自备文件**（推荐，最贴近真实）：≥ 5 页、含封面 / 目录 / 带图片页 / 带表格页 / 结束页，16:9。
- **B. 仓库自带 fixture**：
  ```
  apps/desktop/vendor/genoffice/packages/pptx-engine/tests/fixtures/01_standard_business.pptx
  ```
  5 页，13.33" × 7.5"（12191695 × 6858000 EMU），结构如下：

  | 页 | slide | 内容 |
  |---|---|---|
  | 1 | 0 | 标题 `Q3 Business Review` + 副标题 `Fiscal Year 2026` |
  | 2 | 1 | `Agenda` + 三条列表（Financial results / Product updates / Roadmap） |
  | 3 | 2 | 文本框 `Key Results` + 一张图片 |
  | 4 | 3 | `Revenue by Region` + 表格 |
  | 5 | 4 | `Thank you` + `Questions?` |

  **测试前把它复制一份**，别直接改仓库里的 fixture。

### 2.2 打开方式（关键）

1. 在 EverRoom 产物库/工作区里**以可编辑方式打开**这份 PPT；
2. 确认 `slides_read` 返回 `editable: true`（返回 `false` 说明是只读打开，后续所有编辑都会被拒）；
3. 记下当前版本号，方便回滚核对。

> 文件**不需要**一直在前台：显式传 `fileId` 时未打开也会自动以可编辑方式打开。但为了让「实时显示在视图上」这条可验，建议保持打开。

### 2.3 环境检查清单

| 检查项 | 期望 |
|---|---|
| `slides_read` 能返回大纲 | 每页列出 `元素 id | 类型 | 文本摘要` |
| `slides_read` 返回 `opVocabulary` | 63 项，按 6 组列出 |
| `editable` | `true` |
| 网关连接正常 | 无 `Connection error` |
| 模型输出上限 | 设置里「单次输出上限」建议 ≥ 16384（默认 8192 在长任务里容易触发中断） |

## 三、执行总则

1. **每例独立**：做完一例就 `slides_read` 复核，再进下一例；
2. **留证据**：每例记录「提示词 / Agent 的 ops / 编辑前后大纲差异 / 截图」；
3. **不要替 Agent 补参数**：提示词里不写元素 id、不写 op 名，只描述**用户会怎么说**——这才是要测的东西；
4. **失败必须记录原始错误**（含 `OFFICE_EDIT_FAILED` 之类的错误码），不要只写"失败"；
5. 每轮批量编辑前先 `⌘S` 或等自动保存完成，避免被"文件有未保存修改"拦住。

## 四、测试用例

优先级：**P0** 必过（核心链路） / **P1** 应该过 / **P2** 加分项。

### PP-A 读取与定位

#### PP-A-01 读大纲定位元素 `P0`
- **提示词**：`先读一下这份 PPT 的结构，告诉我一共几页，每页有哪些文字元素。`
- **期望工具调用**：`slides_read {fileId:"active"}`
- **期望结果**：页数正确；每页按大纲列出元素 id 与文本摘要；**不调用 `slides_edit`**
- **判定**：页数与大纲元素数都对得上；没有编造不存在的页或元素
- **失败信号**：不读就直接答；把页数答错；元素摘要与大纲不符

#### PP-A-02 编辑前必读 `P0`
- **提示词**：`把第 2 页的「Agenda」改成「今日议程」。`
- **期望工具调用**：`slides_read` → `slides_edit {ops:[{op:"setText", target:{slide:1, element:<Agenda 的 id>}, …}]}`
- **期望结果**：第 2 页标题变为「今日议程」
- **判定**：只改这一处；副标题/列表不动
- **失败信号**：跳过 `slides_read` 直接编造元素 id；改到第 1 页

#### PP-A-03 只读文件如实拒绝 `P1`
- **前置**：把文件以只读方式打开（或人为置 `editable:false`）
- **提示词**：`把封面标题改一下。`
- **期望行为**：`slides_read` 返回 `editable:false` → Agent 明确告知"当前是只读打开，需要以可编辑方式重新打开"，**不尝试硬改**
- **失败信号**：假称已修改；反复重试同一个必然失败的调用

### PP-T 文本编辑

#### PP-T-01 改标题文字 `P0`
- **提示词**：`把封面标题改成「2026 年第三季度经营回顾」。`
- **期望**：`setText` 作用在封面标题元素；文字**完全等于**该串（不带多余引号、不换行）
- **失败信号**：文字被多余空格/引号污染；改了副标题

#### PP-T-02 保留原有格式只改字 `P0`
- **提示词**：`把「Fiscal Year 2026」里的 2026 改成 2027，字体样式别动。`
- **期望**：`setText` 或 `findReplace`；字号/字重/颜色与原来一致
- **判定**：视觉对比字体无变化
- **失败信号**：改完字号或颜色变了（常见：整段重建 run 丢掉样式）

#### PP-T-03 局部加粗 `P0`
- **提示词**：`第 3 页「Key Results」这行字，把「Key」两个字加粗，其余不变。`
- **期望**：`setText` 拆 run（`[{text:"Key",bold:true},{text:" Results"}]`），或 `setFont` + 拆 run 组合
- **判定**：只有「Key」变粗；返回大纲能看到拆分后的 run 结构
- **失败信号**：整段加粗；文字被改错

#### PP-T-04 批量替换全稿词 `P1`
- **提示词**：`把整份 PPT 里的「Q3」全换成「第三季度」。`
- **期望**：`findReplace`（deck 组），一次事务搞定
- **判定**：所有页命中处都换了；未命中页不受影响
- **失败信号**：逐页 `setText` 硬改（效率低且易漏）；混改大小写

#### PP-T-05 字号统一 `P1`
- **提示词**：`把第 2 页所有正文字号统一成 20pt，标题保持不动。`
- **期望**：`setFont {font:{fontSizePt:20}}` 逐个作用于正文元素（或一次事务多 op）
- **判定**：正文全部 20pt；标题字号不变
- **失败信号**：把标题一起改了；只改了列表第一行

#### PP-T-06 项目符号与行距 `P2`
- **提示词**：`第 2 页那三条列表改成圆点符号，行距 1.3 倍。`
- **期望**：`setParagraphFormat {format:{bullet:…, lineSpacingPct:130}}`
- **失败信号**：用文本手工加 "•" 冒充项目符号

#### PP-T-07 长文本自动换行不溢出 `P1`
- **提示词**：`把第 1 页副标题改长一点：把「Fiscal Year 2026」改成「Fiscal Year 2026 全年经营复盘与 2027 财年规划预告」。`
- **期望**：文本换行后**仍落在原文本框内**，不溢出页面
- **判定**：截图确认文字块未越界；必要时 Agent 主动调整框宽或字号并说明
- **失败信号**：文字溢出到页面外；文字被截断丢字

#### PP-T-08 中英混排不串行 `P2`
- **提示词**：`把标题改成「FY2026 Q3 Review：全年营收与毛利复盘」。`
- **期望**：中英文混排正常，标点不被吞
- **失败信号**：全角/半角符号错乱；换行位置把英文单词劈开

### PP-S 样式与外观

#### PP-S-01 改背景色 `P0`
- **提示词**：`把封面那页背景改成浅灰蓝色。`
- **期望**：`setBackground`（slide 组），色值为具体 `#RRGGBB`
- **判定**：背景变了，文字对比度仍可读
- **失败信号**：给整页盖一个矩形冒充背景；文字看不清

#### PP-S-02 改元素填充色 `P0`
- **提示词**：`第 2 页标题文字改成深蓝色。`
- **期望**：`setFill` 或 `setFont {font:{color:"#…"}}`（文字色优先走字体颜色）
- **判定**：只影响该元素
- **失败信号**：把整页背景改了

#### PP-S-03 加边框 `P1`
- **提示词**：`第 3 页那张图片加一圈 1.5pt 的浅灰边框。`
- **期望**：`setStroke`
- **判定**：边框宽度/颜色对；图片本身没被替换
- **失败信号**：给图片外面套了一根线条形状（不是真边框）

#### PP-S-04 统一标题条样式 `P1`
- **提示词**：`除封面和结束页，其他页的标题都改成 28pt 加粗、颜色 #1F3A5F。`
- **期望**：一次事务多条 `setFont`（≤50 op）；或 `applyTheme`
- **判定**：只影响第 2~4 页;封面/结束页不变
- **失败信号**：漏页/多改；超过 50 op 未拆批导致报错

#### PP-S-05 阴影/发光效果 `P2`
- **提示词**：`给第 3 页那张图片加一点柔和外阴影。`
- **期望**：`setEffects`
- **失败信号**：不支持时如实说明，而不是悄悄不生效

#### PP-S-06 图片透明度 `P2`
- **提示词**：`把第 3 页那张图片调成半透明当背景用。`
- **期望**：`setPictureOpacity`（或 `setImageFill`）
- **判定**：透明度生效，图片位置不变
- **失败信号**：删掉图片再插一张

#### PP-S-07 渐变填充 `P2`
- **提示词**：`第 2 页标题下面的横条改成从左到右的蓝到青渐变。`
- **期望**：`setFill {fill:{stops:[…], angle:…}}`
- **失败信号**：退化成纯色

### PP-E 元素位置与层级

#### PP-E-01 移动元素 `P0`
- **提示词**：`把第 3 页那张图片挪到右下角对齐页面边距。`
- **期望**：`setTransform`，坐标落在页面内、距边约 0.5"
- **判定**：截图位置正确；图片没变形（宽高比不变）
- **失败信号**：图片被拉伸；移动到页面外

#### PP-E-02 缩放元素 `P1`
- **提示词**：`把第 3 页图片缩小到原来的一半，中心位置不变。`
- **期望**：`setTransform` 同时改 `w/h`，`left/top` 相应补偿
- **判定**：宽高减半、中心点基本不动
- **失败信号**：只改宽高不补偿坐标，图片跑到左上

#### PP-E-03 对齐多个元素 `P1`
- **提示词**：`第 3 页的文字和图片顶部对齐。`
- **期望**：`setTransform` 把两者 `top` 设成同值
- **判定**：顶部对齐误差 ≤ 1px（9525 EMU）
- **失败信号**：只动了一个元素

#### PP-E-04 调整层级 `P1`
- **提示词**：`把第 3 页那张图片放到所有文字下面。`
- **期望**：`reorderElement`
- **判定**：图片被文字遮住
- **失败信号**：用删除+重插实现（会丢元素 id/链接）

#### PP-E-05 组合与解组 `P2`
- **提示词**：`把第 3 页的图片和旁边文字组合起来，之后一起移动。`
- **期望**：`groupElements`；成功后再 `setTransform` 验证整组移动
- **失败信号**：组合后无法整体移动（分组不生效却报成功）

#### PP-E-06 翻转/旋转 `P2`
- **提示词**：`把第 3 页那个箭头形状水平翻转。`
- **期望**：`flipElements`
- **失败信号**：改成旋转 180°

#### PP-E-07 更改形状几何 `P2`
- **提示词**：`把第 2 页那个矩形换成圆角矩形，圆角小一点。`
- **期望**：`setShapeGeometry` / `setShapeAdjust`
- **失败信号**：删掉重画，丢原有格式

## 七、常见失败与排查

| 现象 | 原因 | 处理 |
|---|---|---|
| `editable:false`，所有编辑被拒 | 文件以只读方式打开 | 在产物库重新以「可编辑」打开 |
| 报错"元素 id 不存在" | 编辑后 id 会变，用了旧大纲 | 编辑前重新 `slides_read` |
| 报错"超过 50 个 op" | 单事务超限 | 拆批，每批 ≤50 |
| 整批无效但单条看着都对 | 默认 `atomic` | 改 `isolation:"per_op"` 定位失败项，或先 `dryRun` |
| 改了字但样式丢了 | 重建 run 时没带字体属性 | 用 `setText` 时保留原 run 样式，或事后补 `setFont` |
| 版本链没 +1 | 事务没真正落盘（多为校验失败） | 查错误码，看是不是 `OFFICE_EDIT_FAILED` |
| 提示"文件有未保存修改" | UI 里有未保存编辑 | 先 `⌘S`；这类拦截是保护，不是 bug |
| 长任务中途停在"达到模型输出上限" | 单轮输出预算被思考吃光 | 设置里把「单次输出上限」调到 ≥16384；命中后点「继续」 |
| 时间线刷满「已编辑 PPT」 | 拆得过碎（一次一两个 op） | 提示词里要求"一次改完多处"，或看是否触发折叠 |

## 八、判定口径

- **通过**：期望结果全部满足，且 Agent 报告与实际文件状态一致；
- **部分通过**：主要结果达成，但样式/位置有小偏差（记录偏差量）；
- **失败**：结果不符，或 **Agent 声称成功但实际未生效**——这一类必须记为缺陷，优先级最高，因为它会误导用户；
- **不可用**：环境/权限问题导致无法执行（单独记录，不算功能失败）。

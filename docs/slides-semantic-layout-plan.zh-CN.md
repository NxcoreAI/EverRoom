# 从内容规则映射迁移到 Agent 页面设计

日期：2026-10-22
状态：P1/P2 实验链路已接通并完成代码回归；P0/P3 已有真实截图、基线整册和部分重复对照，完整矩阵与人工评审未完成。当前应用模型连接配置为空，无法继续实采。详见 slides-semantic-evaluation.zh-CN.md 与 slides-semantic-implementation.zh-CN.md。
依据：当前工作树，包含正在进行的 Planner / Editor / Layouter / 自审改动。

## 1. 目标与决策

让 Agent 理解内容关系、分配信息优先级并设计整页构图；代码验证输入与产出，确定性完成几何、主题和组件展开。

目标不是让每页都不同，而是：相同用途保持一致，内容关系不同就允许不同表达；完整性、可读性不因追求变化下降。

第一版选择：

1. 在现有 `slides-planner` arrange 调用内产出页面理解和页面文案，不为每页新增理解 Agent。
2. `slides-layouter` 根据页面理解、实际可用素材、全册风格与邻页摘要决定构图和组件位置。
3. 保留现有 v2 布局语法、组件库、主题、编译器和真实渲染自审。内容契约升级与布局语法版本分开管理。
4. `slides-editor` 继续负责指定页的内容修复，不恢复整册第二次 LLM 压缩。
5. 不再用要点数量推断内容关系，不把关系标签映射为唯一骨架，不用形态配额制造变化。
6. 上线评估采用同一份已确认草稿、相同风格和素材进行比较，额外报告内容编排本身的差异。

## 2. 当前问题与迁移位置

| 位置 | 当前行为 | 迁移后的职责 |
|---|---|---|
| `agents/slides-planner` arrange | 标题、短要点、角色、密度、配图；最多三条要点 | 输出可追溯的页面内容与理解；数量由表达需求和观看场景约束 |
| `slides-condense.ts` | `decideForm` 数量分类；按 form 预算选择 facts/supporting；其余转讲稿 | 验证、规范化和装配；不根据标签裁剪内容 |
| `slides-page-form.ts` | 九类形态、配额、构图与骨架映射 | 新路径解除依赖；迁移结束后清除在线语义推断职责 |
| `slides-editor.ts` | storyboard/v2 形态、文案及全册配额检查 | 内容来源、引用关系、优先级、用途与完整性检查 |
| `slides-layout-tail.ts` | 传 composition/skeleton；减配重试；图片缺失重推 composition；失败页 | 传完整内容契约；素材变化反馈；重试不丢必留内容；失败明确记录 |
| `agents/slides-layouter` | 读骨架填 slot；内容页至少四模块；自审看图 | 理解关系后设计构图；组件为表达服务；自审同时检查信息关系 |
| `tree/v2/schema.ts` | composition 必填，按家族验证附加约束 | 保留布局 v2；composition 由 layouter 声明，按实际节点检查 |
| `tree/similarity.ts` | 邻页同签名打回重排 | 相似度提供证据；相同用途与连续比较页允许重复 |
| `tree/v2/richness.ts` | 内容页必须图形且至少四节点 | 去掉固定模块数和装饰凑数要求；以可读性、关系表达为准 |

特别处理：Planner 和 Layouter 已有 `toc`，但当前 Editor 角色枚举不包含它。页面用途必须贯穿所有 schema、规范化、预算与回传，不能把目录归一成普通内容页。

## 3. 新内容契约：storyboard/v3

这是内容契约版本；布局树仍是 `version: 2`。单一权威类型和运行时校验集中在内容 module，其他环节使用同一 interface。避免各 Agent schema 单独维护不同词表。

### 3.1 来源与页面理解

网关在 arrange 前给用户确认的草稿页、要点、数据和素材分配稳定 ID，随 arrange 输入传入；不依赖改写后的文字定位来源。重新编排保留来源引用，页码只是展示序号。

每页至少包含：

| 字段 | 含义 | 使用方 |
|---|---|---|
| `id / sourceRefs` | 页面 ID、对应草稿内容 | 存储、修复、追溯 |
| `role` | cover / toc / section / content / data / table / flow / quote / closing | 标题、导航、页级约束；不绑定模板 |
| `message` | 页面主题或核心结论；目录、封面不强行写论证结论 | Layouter 确定主焦点 |
| `blocks` | 可展示内容单元，含 ID、类型、文案或结构化数据、来源、优先级 | Layouter 组合表达 |
| `relations` | 单元之间的关系、引用的 block ID、简短依据 | 设计并置、顺序、连接、层级和共同维度 |
| `focusRefs` | 期望优先被读到的内容，通常一个焦点，可包含一组比较对象 | 视觉主次 |
| `constraints` | 必留内容、原文引用、完整展示或允许裁切的素材等 | 校验与自审 |
| `notes / omissions` | 讲稿和未展示的来源内容及原因 | 内容追溯 |

第一版 block 类型收敛为 `text / metric / quotation / table / chart / image`，不新建庞大领域语言。关系使用 `supports / compares / precedes / causes / contains / parallel / navigates` 等有实际设计用途的词，允许一页多种关系、允许为空。字段枚举约束表达方式，不决定构图。

内容优先级为 `primary / supporting / detail`，是否必须上页由独立的 `mustShow` 标识，不能把“次要”当作“可删除”。

关系示例：

```json
{
  "message": "新方案把交付周期缩短一半",
  "focusRefs": ["old-cycle", "new-cycle"],
  "relations": [{
    "type": "compares",
    "refs": ["old-cycle", "new-cycle"],
    "basis": "同一交付口径下的周期，单位都是天"
  }]
}
```

示例省略 blocks。此处只表达内容，不包含左右分栏、栅格或组件名。

### 3.2 内容保留与结构化数据

1. 在已确认草稿到 arrange 结果之间，记录来源覆盖：展示、转讲稿或明确遗漏原因。用户指定必须展示的信息不允许只进讲稿。
2. 结构化 table/chart/metric 由 Planner 直接提交数据对象，校验行列、数值、单位和来源。原来的 data 字符串解析仅作为旧输入转换，不承担新内容分类。
3. 普通文案允许有来源的压缩与改写；数值、单位、表格数据、直接引用须保真。正则匹配可以检查格式，不能证明语义正确。
4. 内容预算由观看场景、字号下限和真实测量决定；提前给出建议预算，不按关系标签截取前 N 条。
5. 装不下时返回明确容量缺陷，由 Editor 压缩允许改写的内容。页数变化遵守用户约束；页数固定时不得自动拆页。
6. 拆掉“每页必须压成一句结论加一行支撑”的通用限制，保留不同用途所需的信息容量。

## 4. 版式决策与验证

### 4.1 Layouter 的输入和决定

输入：当前页完整内容契约、实际素材及尺寸、风格 token、观看场景、邻页用途与简短内容摘要。单页任务不携带整册全文。

Layouter 自主决定：

- 表达结构：比较、轨道、层级、图中标注、共同坐标、数据主体等；无固定形态到骨架映射。
- 主次面积、阅读顺序、对齐、留白、出血与图文关系。
- 组件选择、栅格区域、group 比例和组件语义样式。

输出复用现有提交结果，增加简短 `designIntent` 和 `bindings`：前者说明焦点、阅读路径及重要关系的表达方式，后者把 block ID 对应到布局节点路径。它们属于设计结果元信息，不进入 PPT 正文，也不改变引擎布局树。

composition 在第一版继续保留，改由 Layouter 根据其设计声明，取消“必须照抄上游”要求。现有家族约束只检查声明是否成立；不作为自动选版菜单，也不拿家族数量衡量质量。是否移除该字段，待新路径稳定后另行决定。

组件库提供局部稳定排版和能力范围，不接入 `tree/v3/skeletons.ts` 的整页自动选骨架。

### 4.2 校验分工

确定性代码检查：

- schema、来源 ID、关系 ID、bindings 路径和数据结构有效。
- mustShow 内容没有漏绑定，绑定节点确实存在且有对应载荷；不能仅凭 Agent 自报“已展示”放行。
- 数值、单位、表格行列和引用内容与内容契约一致；按渲染内容检查，图表允许合法的格式化表示。
- 编译、溢出、字号下限、文字对比度和素材可用性。按节点用途判断遮挡，避免把有意叠图判为缺陷。

Agent 结合内容契约和渲染图检查：

- 核心信息是否明显，比较对象是否能对应，层级和先后关系是否读得出来。
- 改写是否保留原意，图片裁切是否损伤主体，整体是否严重拥挤或失衡。

bindings 只能证明对应关系和部分内容覆盖，不能证明语义或可见性；自动检查不宣称能确定性证明“理解正确”。

复用现有“两次调用：设计、渲染后自审”，第一版不增加独立审稿 Agent。自审修改后重新测量；若布局变化，最终版本必须重新渲染验证，禁止只验旧截图。

### 4.3 全册一致性与变化

保留全册风格 token、稳定导航和素材处理规范。相似度审计考虑页面用途、内容关系和几何特征，重复仅作为审查信号。

连续参数表、案例页或章节目录可以使用相同布局；不同内容反复使用相同空间结构才需要重新评估。允许一次有明确依据的指定页重排，最终改动仍经过完整校验和渲染。取消每对同签名必须不同构的规则。

删除新路径中 breakdown ≤50%、≥8 页至少三种 form 等配额；密度、主焦点面积、留白和节点数量作为诊断信息，不直接等同于审美质量。

## 5. 实施阶段

各阶段都能独立审阅，完成验收后再进入下一阶段。

### P0：固定比较样本与内容 interface

- 用当前工作树固定生成基线，记录版本、模型配置、风格、素材、输入和真实输出；不把 HEAD 当作当前代码的等价基线。
- 建立来源 ID、storyboard/v3 类型、共享校验与 schema 一致性检查；定义容量失败、来源缺失、设计失败的错误语义。
- 固定至少 12 个单页样例及 3 套完整草稿：融资 BP、内部汇报、教学或产品说明。
- 必须覆盖：两项并列收益与两方比较、流程与目录、层级与并列列表、表格与指标、大图与无图、长内容、必留引用。

验收：接口样例可验证；旧数据仍能读取；基线报告包含真实截图和缺陷，不以形态数代表视觉多样性。

### P1：Planner 产出理解，内容装配停止推断

- 修改 Planner arrange 输入和输出 schema、提示词及调用侧白名单，加入来源、blocks、relations、focusRefs、constraints。
- 新增内容 module，把规范化、校验、来源覆盖及修复输入放在一个 interface 后；`tools.ts` 负责调度。
- 新路径绕开 `decideForm / settleDistribution / factsMaxForForm / deriveSkeleton`，不再自动丢掉长要点或硬切标题。
- Editor 按指定页修复新内容契约，保留原有最多两轮、每轮最多四页的资源上限。
- 单独打通 toc；来源、页 ID 不随重排或配图阶段漂移。

验收：同数量不同关系的样例得到可解释的不同关系；必留信息不丢；代码检查不依赖旧 form；正常情况没有额外理解调用。

### P2：Layouter 自主构图，接通内容覆盖检查

- 修改 Layouter 输入、输出、提示词及权威布局文档；同步生成技能文档。
- 接通 designIntent、bindings、字段白名单、缩配重试、素材 QC 和页级重试。
- 删除新路径的 composition/skeleton 上游锁定；图片被移除时更新实际素材，再请 Layouter 按原内容重排。
- 保留栅格、主题和组件展开；解除固定四模块、装饰凑数和强制邻页不同构要求。
- 自审与全册重排均不得新增事实或降低 mustShow 覆盖。

验收：所有设计与修正均通过几何和内容校验；最终图可追溯到最终树；缺图和超容量不会静默删内容。

### P3：真实产物对比与启用

- 单页测试隔离版式效果：相同内容契约、风格、素材，新旧路径各生成至少三次。
- 整册测试比较最终效果及来源覆盖，记录内容编排变化，避免把删内容造成的“更清爽”算作改进。
- 匿名成对评审：关系表达、重点清晰、阅读顺序、全册一致性、无意义重复。
- 记录成功率、容量返工、溢出与遮挡、内容遗漏、设计耗时 P50/P95、模型调用和 token 成本。
- 数据足够后默认启用新路径，再删除旧生产映射，保留历史内容与 v2 布局的读取能力。

建议启用门槛：固定样本中必留信息无遗漏、无数值和引用变造；阻塞几何缺陷为零；最终输出均有渲染验证。成对评审新路径获得至少三分之二偏好，且没有持续退化的页面用途。正常理解调用数不增加，端到端 P95 和每册 token 相对基线增幅目标各不超过 20%。样本较小，以上是启用门槛而非统计显著性结论；若质量改善需突破成本目标，报告实测后单独决定。

## 6. 失败处理、存储与回退

- 每次生成固定内容契约版本和模式，不能一页新语义、一页旧数量映射。模式随持久化记录和恢复任务保存。
- 新语义缺失或校验失败时走指定页修复；仍失败，保留来源、已完成页面和可重试状态。不得静默切回旧分类或生成只有标题的“成功页”。
- 内容完整、几何通过但视觉自审不可用时可保留结果，明确记录未验证状态；不能记作通过启用门槛的样本。
- 读取历史 storyboard/v2 保持兼容；新结果存 storyboard/v3。内容哈希之外需区分契约版本、生成配置和实际素材，避免旧记录或幂等结果覆盖新实验。
- 当前 `SlidesStoryboardStore.save()` 按 room/draft/hash 覆盖：实施时扩展记录键或版本元数据和查询条件，验证旧记录迁移；不能只在 JSON 里加版本后继续覆盖比较结果。
- 运行模式开关已删除（2026-10-22 起 semantic-v3 是唯一内容路径）：legacy 链路整体下线，没有按任务回退旧链路的开关；历史 deck 仍按其保存的契约读取渲染。

## 7. 检查范围与交付

按变更阶段运行：gateway 类型检查；Planner/Editor/Layouter schema 和来源覆盖测试；condense/editor/tools/layout-tail 回归；v2 编译、组件和相似度测试；存储迁移和任务恢复测试；权威语法与生成技能一致性检查。

重点验证行为：两条内容不自动成为对照、流程不因数量成为并列、目录不变成普通内容、表格数据完整、来源变更使缓存失效、缺图重排保留信息、重试/自审/最终重排不漏必留内容。

阶段交付包括：内容契约及样例、可比较的旧基线、新路径实现、真实截图与整册纵览、质量和成本对照报告、启用或暂缓结论。按 P0 → P1 → P2 → P3 推进，本计划不授权在未验证时直接切换默认生成链路。

# 导入 PowerPoint 文件制作可复用模板：功能规划

日期：2026-10-23
状态：方案讨论与实施规划，尚未实现；技术可行性依据现有代码检查，识别质量与生成效果需要样本验证。

## 1. 目标与已确认方向

用户导入 `.potx` 或 `.pptx`，系统利用文件结构和页面截图，识别可替换的文字、图片区域及应保留的固定元素。用户确认后保存为 EverRoom 模板，后续用新内容选择合适版式、填充并生成可编辑 PPTX。

两种输入共享一套处理流程，不按扩展名判断模板质量：

- POTX 表示文件用途是演示文稿模板，不保证其中存在规范占位符。
- PPTX 也可以包含完整母版、版式和占位符；不需要先转换成 POTX 才能复用。
- 存在明确占位符时，优先利用结构信息建立候选区域；仍需检查可用性和容量。
- 没有占位符时，允许视觉模型理解截图，通过几何、文本及文件元素清单建立绑定。
- 模板以原始 OOXML 内容为基础保存和实例化，保留原页设计；不要求先将所有设计转换成现有布局树。

本文中“导入模板”包含导入、识别、确认、保存和后续按模板生成，不能仅以文件打开成功或视觉分析成功作为完成标准。

## 2. 文件结构与产品术语

| 概念 | 含义 | 在本功能中的用途 |
|---|---|---|
| POTX / PPTX | Office Open XML 文件包，前者为模板类型，后者为演示文稿类型 | 输入文件类型，需校验包内内容类型，不只检查后缀 |
| 主题 Theme | 字体、颜色及效果定义 | 保留原模板风格与继承关系 |
| 母版 Slide Master | 被版式和页面继承的公共样式、背景和装饰 | 保留公共品牌元素，避免填充时改动所有页面 |
| 原生版式 Slide Layout | 母版下的具体页面结构，可包含占位符与固定图形 | 从版式生成新页，尤其适合规范 POTX |
| 原生占位符 Placeholder | 由 `p:ph` 等结构标记类型及编号的内容区域 | 为标题、正文、图片等提供结构线索，不等于业务字段 |
| 模板页型 Template Page | EverRoom 中可供新内容选择的一种页面 | 可以来自原生版式，也可以来自一张普通成品页 |
| 模板槽位 Template Slot | 经确认可填充的内容区域 | 绑定一个或多个文件元素，描述用途、填充方式及容量 |
| 模板版本 Template Version | 原始文件、页型、槽位及确认结果的不可变快照 | 保证后续生成可复现，避免重新导入后引用错位 |

原生占位符通常只表达“标题 / 正文 / 图片 / 通用内容”，不会自然提供“融资金额 / 团队姓名 / 产品卖点”等业务语义。业务用途、重复项关系、容量以及是否可替换，仍由识别和用户确认补充。

首版不支持旧二进制 `.pot/.ppt`、宏格式和 PDF/截图转可编辑模板。以后增加转换入口时，应单独披露转换对格式和元素身份的影响。

## 3. 现有能力与缺口

以下依据当前工作树，不代表这些模块已经可以直接拼成完整功能。

| 位置 | 已有能力 | 本功能需要补齐 |
|---|---|---|
| `apps/gateway/src/modules/subagents/slides-reference.ts` | PPTX/PPT 转 PDF 和图片，抽取参考配色、密度及标题 | 这是视觉参考入口，没有原始元素绑定、模板持久化和填充流程 |
| `apps/desktop/vendor/genoffice/packages/pptx-engine/src/index.ts` | `openPptx`、`savePptx`、复制页面、保留源格式粘贴、按版式插页 | POTX 包类型验证、无示例页模板实例化、源到目标元素映射、模板填充事务 |
| 同上 `replacePictureBytes` | 为普通图片创建新媒体及关系，保留图片框和效果 | 槽位级裁切策略、组合内图片替换及重复实例隔离验证 |
| `pptx-engine/src/layout.ts`、`placeholder.ts`、`parse.ts` | 版式枚举、占位符解析、母版/版式样式与几何继承 | 导入描述符需完整保留 type/idx；现有快速版式清单会跳过图片和部分无显式几何的占位符，不能直接当作完整槽位清单 |
| `pptx-engine/src/identity.ts` | 原始元素持久标识、形状 ID 及组合子元素辅助定位 | 不直接保存运行时随机 ID；版本、源 part 路径与元素身份一起构成定位依据，并检查碰撞 |
| `apps/gateway/src/modules/slides-style/render.ts` | 通过 LibreOffice 渲染单页截图，管理超时和临时目录 | 原文件多页及版式探测页渲染、完整画布坐标变换、字体及渲染器版本记录 |
| `slides-semantic-contract.ts`、`slides-semantic-bindings.ts` | 页面内容契约、来源与必留信息校验 | 新增内容块到模板槽位的绑定及最终文件载荷校验，不能直接复用布局树路径作为文件元素引用 |
| `slides-layout-tail.ts` 及现有生成编排 | 自由生成、测量、截图与视觉复核 | 增加模板生成模式；原页内容不经自由布局编译器重建 |

外部图表不能视为已有通用编辑能力：当前 `editChartElement` 限制为本应用创建的图表。原始图表可保留，但首版不承诺替换外部图表数据或保持其复杂格式。

## 4. 用户流程

### 4.1 导入与制作模板

1. 选择 POTX/PPTX，创建导入任务并保留原始文件快照。
2. 分析包结构、原生版式、页面、元素和字体，显示可处理范围及不支持项。
3. 生成源页面预览；没有示例页的原生版式，在临时副本中生成探测页后预览。无占位符的空白版式不能自动成为可用内容页型。
4. 系统提出页型和槽位建议，在源预览上显示绑定区域及固定区域。
5. 用户选择保留哪些页型，确认或修改区域用途、可替换性、组合关系及填充约束。
6. 进行试填并预览，通过检查后发布一个可复用模板版本。

初版所有待发布页型都经过用户确认。高置信度只用于减少检查负担，不代表可以跳过确认，也不能自动解锁母版公共元素。

### 4.2 用户确认界面

- 页型列表：预览、名称、用途、已确认状态和阻塞问题。
- 页面预览：点击区域可定位对应文件元素，侧栏显示原文或图片、建议用途、是否固定以及依据。
- 支持把多个文本框归为一个逻辑区域，也支持拆分识别错误的区域；关联的装饰元素可标为保留。
- 支持指定标题、正文、图片、指标、引用等用途；业务名称为可编辑标签。
- 显示未绑定的原页文字、未确认区域、字体缺失和不支持对象，避免旧公司名、旧数据被当作装饰带入成品。
- 发布前提供试填预览，用户可以返回修正；识别和试填结果保存到该导入会话。

### 4.3 使用模板生成

1. 用户选择已发布模板版本并提供新内容，沿用当前草稿确认流程。
2. Planner 读取页型摘要与槽位容量，在保留内容来源的前提下提出选页及绑定计划。
3. 系统验证页型适配、必留内容覆盖和填充能力，执行页面实例化及内容替换。
4. 对实际填充结果进行文本/数据检查、量测和最终截图复核，输出可编辑 PPTX。
5. 无合适页型或内容装不下时，返回明确问题。需要拆页或改页数时遵守用户约束；切换自由生成须由用户选择。

## 5. 技术流程：文件解析与视觉理解协作

### 5.1 原始元素清单

从文件解析每页及原生版式的候选元素，至少包含：

- 源文件哈希、页型来源 part、母版/版式关联及页面尺寸。
- 原始元素身份、组合祖先链、元素类型、层级和所属层：slide / layout / master。
- 原始完整文本、段落和样式摘要；图片媒体引用及可用缩略图。
- 局部几何、合成后的页面变换、旋转/翻转、裁切、可见性和遮挡线索。
- 已知占位符 type/idx、形状名称等提示信息，以及支持的编辑操作。

组合子元素必须结合 `chOff/chExt`、父级缩放、旋转和翻转计算到页面坐标；不能把局部 x/y 直接与截图比较。完整变换暂时无法解析的元素标为不支持自动绑定。

### 5.2 截图与坐标基准

截图来自同一源版本，保持完整页面及宽高比，记录图像尺寸和页面到像素的变换。如果添加了边距、缩放或裁切，必须在转换中显式记录。

原始源文件使用固定渲染配置建立基线；试填和最终产物使用同一配置复核。桌面预览可能使用不同渲染器，需检查主要视觉差异，不能仅因为使用同一截图渲染器就宣称与 PowerPoint 完全一致。

缺字体或替代字体会改变换行、文字范围及容量。字体状态必须进入分析结果；对布局有明显影响时阻止自动发布或要求用户在目标字体环境重新验证。

### 5.3 视觉模型输入与输出

视觉模型负责理解可见页面：识别标题、正文、图片区、重复项目、固定品牌区域及阅读顺序，不直接生成 OOXML 或执行修改。

输入为单页干净截图及经裁剪的元素清单，必要时附带带候选编号的辅助图。候选编号由系统绑定到解析结果，不由模型创造；辅助编号遮挡内容时以干净截图为准。

模型输出结构化区域、建议角色、文本片段、归一化边界框、候选元素引用、判断依据及不确定项。图中文字、形状名称和备注均属于待分析数据，不作为对模型的操作指令。

### 5.4 确定性匹配与消歧

匹配不只依靠模型报出的框，也不只使用 IoU：

- 文本：优先结合文件原文、文字排列、空间位置和候选身份；截图 OCR/模型转写只辅助匹配，不能覆盖源文本作为事实。
- 图片：结合原图缩略图、裁切、几何、层级及对象类型；区分普通图片、背景填充和形状图片填充。
- 重复文本或重复图形：结合相对位置、分组、邻接元素和阅读顺序消歧。
- 一个视觉区域可绑定多个元素；几何大框内有装饰时，不能把装饰一并判为替换目标。
- 候选引用必须存在于当前源版本；检查唯一性、类型、可编辑性和冲突，拒绝虚构 ID。

输出分别记录结构证据、几何/文本匹配证据和模型建议。模型自报置信度不当作已校准概率；自动推荐阈值通过标注样本确定。证据矛盾、多个同分候选或元素不可编辑时进入用户确认。

“这里是标题”与“该标题应被替换”是两项独立判断。母版文字、固定品牌名、页眉页脚和来源说明必须单独确认。

### 5.5 绑定确认与试填

绑定成功不等于填充成功。发布前使用短文案、长文案及不同宽高比图片试填，检查实际的换行、裁切、字号和固定元素保留情况。

一段标题跨多个文本框时，区域可保存多个引用，但必须声明如何分配内容。首版自动填充只支持已验证的单元素槽位或明确的多目标策略；不能简单把同一文案写入所有元素。需要任意拆字、特殊字效或复杂跨框排版的区域保留为待人工处理。

## 6. 内部模板契约草案

新增独立的模板版本契约，例如 `slides-template/v1`，不替代 `storyboard/v3` 或现有布局树版本。以下为规划字段，实施时统一类型、运行时校验和持久化定义。

| 对象 | 关键字段 |
|---|---|
| TemplateVersion | templateId、versionId、schemaVersion、sourceHash、sourceAssetRef、contentType、analysisConfig、状态 |
| TemplatePage | id、source（slide 或 layout）、sourcePart、masterPart、role、previewRef、slots、fixedRefs、issues、确认记录 |
| ElementRef | sourceHash、sourcePart、完整 creationId 或源 shapeId、组合祖先路径、原始类型及可选指纹 |
| TemplateSlot | id、role、label、elementRefs、writeStrategy、constraints、匹配证据、确认状态 |
| FillPlan | templateVersionId、内容来源快照、各页 pageTypeId、各 blockId 到 slotId 的绑定及预期操作 |
| PageInstance | 新页面身份、源页型、源到目标元素映射、最终填充状态及验证记录 |

`writeStrategy` 首版可以包含 `replaceText`、`replacePicture`；多目标区域使用显式目标分配表。固定元素不生成写操作。页码、日期和目录若需自动更新，作为受控动态字段单独声明，不能直接沿用源样例值。

`constraints` 表达允许的内容类型、必填/可空、文字范围与保留格式策略、字号下限、图片 contain/cover 和内容容量建议。字数只能作为早期提示，实际容量以目标字体下的量测和最终渲染为准。

重要约束：

- 元素引用必须限定在源文件版本和 part 内；现有短 ID 不视为全局唯一，复制页面后必须构建目标映射。
- 相同图片资源可以被多个对象共享，媒体路径不能替代元素引用。
- 用户重新上传或修改原文件后建立新版本；旧映射不自动套用，旧生成任务继续固定旧版本。
- 保存原始示例内容供分析追溯，但不能把示例当作新任务的数据来源。
- 隐藏页、未选页面、备注和其他非预期内容在生成输出前按明确规则排除或重建，避免旧内容残留。

## 7. 填充执行与现有生成链路接入

### 7.1 模块职责

| 边界 | 职责 |
|---|---|
| 桌面 Office/引擎层 | 原文件解析、变换与身份解析、渲染支持、页面实例化、元素补丁、保存与重开验证 |
| Gateway 模板服务 | 导入会话、模型调用与结果校验、模板版本存储、选页/绑定编排、验证记录和恢复 |
| Renderer 模板界面 | 页型选择、区域高亮、确认修正、试填预览和模板管理 |
| Planner / 内容层 | 产生有来源的内容、选择页型、适配槽位；不猜文件坐标、不直接修改 XML |

通过现有桌面 Office 桥的模式提供必要接口，具体接口位置在实施时结合现有协议确定。Gateway 不依赖前端正在打开的可变文档状态；长任务均引用源版本和工作副本。

### 7.2 生成执行

- 自由生成与模板生成共享草稿、内容来源、素材和部分质量检查；模板生成单独实例化源页面/原生版式。
- 新增显式生成模式及 `templateVersionId`，每个任务固定模式和版本。
- 母版和原生版式默认保持固定。需修改其内容时优先在实例页内覆盖，禁止无意改动共享源定义。
- 普通文本替换保留约定的段落和样式；混合字体、分段着色与多段落必须定义明确处理策略，不能仅保留首个 run 就宣称格式保真。
- 图片替换保留原框、层级及可支持效果，根据新图尺寸重新计算裁切；不得直接覆盖共享媒体资源。
- 复制含图表等共享依赖的页面后，对需要修改的资源执行独立化；首版不修改不支持的对象。
- 填充在隔离工作副本完成，校验后再发布结果；原始模板不被生成任务修改。
- 输出为正确的 PPTX 内容类型，不能仅把 POTX 文件改后缀当作生成结果。

### 7.3 容量和失败处理

同一个页型不能容纳任意内容。对三栏页新增第四项、超长标题、不可改写引用或大表格，先返回适配问题，再选择其他合适页型；允许拆页时重新规划并说明变化。

固定页数、必留内容、原文引用和数值保真优先于填满模板。不得靠静默删内容、无限缩小字号、保留旧数据或把必留内容移到备注来通过检查。

没有合适页型时标记 `no_compatible_page_type`；不支持的编辑标记 `unsupported_slot_operation`；内容装不下标记 `content_capacity_exceeded`；绑定歧义、字体缺失和渲染失败分别记录。失败页可修正后重试，不伪装成已完成页面。

## 8. 范围与分阶段实施

### P0：样本与最小验证

准备至少 8 份可合法用于验证的 POTX/PPTX、合计至少 40 个候选页型，包含：规范占位符模板、无示例页 POTX、普通文本框成品页、重复文案、图片裁切、组合、母版固定文字和复杂对象。

人工标注可替换区域、固定区域、目标元素和不支持项。至少留出一部分独立文件作为保留评估集，不能只按页随机拆分同一套模板。

验证三条最小闭环：原生版式到新页；普通成品页截图到文本/图片元素绑定；复制同一页两次分别填充、保存并重开。对比坐标与候选编号方式，测量识别和修正成本。

交付：样本清单、标注、预览、试填 PPTX、逐项失败报告及继续/收窄范围的结论。未通过此阶段前不承诺自动识别准确率。

### P1：结构化模板导入

- 支持 POTX/PPTX 包检查、原生版式和占位符解析、预览以及模板版本存储。
- 提供页型/槽位确认界面，优先支持已验证的文本和普通图片填充。
- 支持空示例页 POTX 的版式实例化，明确处理继承样式、图片占位符与输出文件类型。
- 形成单页和小册试填闭环，验证源文件不变、实例隔离和保存重开。

### P2：普通页面视觉模板化

- 接入单页视觉模型、候选元素辅助图、文本/几何匹配及歧义反馈。
- 支持无占位符的普通文本框、普通图片，以及可以可靠换算和编辑的组合子元素。
- 提供多元素逻辑区域和显式填充策略；复杂写入策略先保留为手工确认或不支持。
- 用户可修正模型识别，确认结果作为版本内容保存。

### P3：整册生成与恢复

- 接入现有草稿及 `storyboard/v3`，新增按模板选页和内容块到槽位的绑定计划。
- 实现容量反馈、最终文件载荷检查、截图复核、任务进度与中断恢复。
- 验证重复页型、多章节、固定页数、不同内容密度和图片缺失等整册场景。

### 后续能力

外部表格/图表数据更新、复杂 SmartArt、背景图像替换、可增减重复项、自动伸缩版式和低干预自动发布均单独评估。初版支持模板固定区域保留，不等于支持修改其中所有对象。

## 9. 验证与验收

| 维度 | 检查内容与建议门槛 |
|---|---|
| 解析和身份 | 槽位引用存在且唯一；保存重开仍可定位；复制后目标映射有效；自动接受结果中不得有悬空引用 |
| 定位质量 | 在保留评估集上统计普通文本/图片的元素匹配准确率、召回率与歧义率；自动推荐候选的精确率目标至少 98%，需报告样本量、分类型结果及用户修正率 |
| 保守性 | 标注为固定的 Logo/装饰不得被自动填充覆盖；源模板和其他页面实例不得被连带修改 |
| 内容完整性 | 必留内容无遗漏，数值/单位/引用无变造，示例文字与旧数据无意外残留；备注和隐藏页按输出规则处理 |
| 视觉效果 | 最终保存版本重开并渲染；无阻塞溢出、字号违规或主体裁切；人工确认固定区域与模板一致 |
| 格式 | 输出 PPTX 可被引擎及目标 PowerPoint 环境正常打开，无修复提示；内容类型与后缀匹配 |
| 产品闭环 | 导入、确认、试填、发布、选用、生成、失败修正和恢复可完成；无静默模式切换 |
| 成本与效率 | 记录每页/每文件耗时 P50/P95、视觉调用与 token、渲染耗时、用户确认耗时；P0 建基线后确定上线预算 |

98% 是规划目标，不是当前能力结论，也不表示允许错误写入。发布前确认、操作白名单及最终结果验证共同约束实际修改；困难样本应明确拒绝自动处理。

实施测试重点：坐标变换及旋转/组合、重复文本消歧、占位符继承、图片裁切与资源隔离、文本样式、源版本失效、POTX 无示例页、两实例独立修改、保存重开、内容覆盖及任务恢复。模型识别采用标注集评估，确定性测试不以固定模型自然语言回复作为唯一依据。

## 10. 持久化与任务状态

导入会话建议状态为 `uploaded → analyzing → needs_confirmation → trial_filling → ready`，异常单独记录 `failed` 或 `unsupported`。会话可以部分完成，但只有通过验证并确认的页型进入已发布版本；版本发布后不原地覆盖。

保存原文件、预览、元素清单、模型结果、匹配证据、用户修订、试填结果及配置版本。模型和渲染缓存至少按源哈希、分析配置、渲染配置及模式区分，不能把旧截图的绑定结果复用于已修改文件。

生成记录固定模板版本、内容快照、FillPlan、目标元素映射、实际操作和验证结果。恢复任务以已确认快照继续，重试不能重复插页或重复替换；取消后未发布副本不进入模板库或正式成品。

文件大小、ZIP 展开量、页型数量、媒体大小、模型并发与渲染超时需要设置可配置上限。分析不执行宏或外部链接，外部媒体缺失明确报告；原文件及截图按现有文件权限和模型数据处理配置使用。

## 11. 待样本验证的决策

1. 首版模型是否同时接收完整元素清单，还是先视觉识别再返回局部候选；依据效果、token 和耗时选择。
2. 每类页型容量的默认试填内容与字号下限，是否需要区分投影展示和阅读用途。
3. 组合内多框文字的首批可支持写入策略，以及必须交给人工的边界。
4. 原生空版式、普通成品页如何在界面中统一展示，如何避免默认收录无用的 Office 内置空白版式。
5. 全册固定日期、页码、目录、版权及公司名称的替换规则；没有明确规则时不能自动推断为可变字段。

下一步从 P0 开始，用真实企业模板和普通成品页验证定位、填充及实例隔离。评估通过后按 P1 → P2 → P3 接入产品，不以截图理解成功代替完整模板生成验收。
